# AI·검색 증강 판정 기록(AI_SCOPE)

> 아로새김에는 생성형 AI가 없다. 이 문서는 "왜 없는가"를 판정으로 기록하고,
> 나중에 조건이 갖춰지면 다시 판단할 후보와 그 기준을 남긴다.
> 근거 표기: ADR-번호 = docs/ADR.md의 설계 결정, F·Q-번호 = docs/DEV_LOG.md의 확인된 사실·열린 질문,
> ARO-F*-AC* = docs/spec/ac/의 수락 기준.
> 상태 어휘: 쓰지 않음·불필요·해당 없음 = 지금도 앞으로도 넣지 않는다. (구상) = 지금은 만들지 않고, 조건이 갖춰지면 다시 판단한다.

## 한눈에 보기

- 결론: 앱·서버·웹 어디에도 생성형 AI는 없다. 해설·퀴즈는 사람이 쓴 문장을 시드 파일로 넣고, 도착·스탬프·포인트는 규칙이 판정한다(ADR-002·ADR-011, 개발 기록 F24).
- 이유: 유물 해설은 틀리면 곧바로 잘못된 역사가 되는 문장이고, 주행 중에는 입력 자체가 막히며, 필요한 문장은 미리 다 준비할 수 있는 규모다. 차량 플랫폼의 언어 모델 SDK(소프트웨어 개발 키트)는 제공이 끝났다(개발 기록 F24).
- 떠난 가족의 목소리를 AI로 다시 만들지 않는다는 원칙도 함께 지킨다(개발 기록 F40, ADR-007).
- 이 문서는 AI 관련 질문에 답할 때 쓰는 판정 기록이다. 기능 사양이 아니므로 어떤 기능도 새로 만들지 않는다.

### 이 문서를 쓰는 곳 · 쓰지 않는 곳

- 쓰는 곳: "AI를 쓰나요, 왜 안 쓰나요?"라는 질문에 대한 공식 답. 2차 고도화를 검토할 때 이 표의 조건을 다시 읽는 출발점. 기획서·README의 AI 관련 문장이 인용할 근거.
- 쓰지 않는 곳: 기능 수락 기준 목록(docs/spec/ac/)의 항목이 아니다. 화면·동작을 정의하는 사양이 아니므로 코드·시험과 대응하는 항목을 만들지 않는다. AI 기능이 있는 것처럼 읽히는 문구의 근거로도 쓰지 않는다.

## 1. 판정 표

| 후보 | 판정 | 이유(근거 번호) |
|---|---|---|
| 도착 해설·퀴즈 문항을 LLM(대규모 언어 모델)으로 생성 | 쓰지 않음 | 차량 플랫폼 언어 모델 SDK 제공 종료(개발 기록 F24). 유물 해설은 환각(사실이 아닌 문장을 그럴듯하게 만드는 현상)을 받아들이지 못하는 자리다. 해설·퀴즈는 사람이 직접 쓰고 `reviewed`(검수 여부) 플래그로 검수한다(assets/seed/seed.json 머리 주석, domain/Models.kt, 개발 기록 F19) |
| 주행 중 자유 입력 음성 비서 | 쓰지 않음 | 주행 중에는 앱 화면이 시스템에 가려져 입력이 열리지 않는다(개발 기록 F68 실측). 주행·정차 신호가 어긋나도 더 제한적인 쪽을 우선한다(ADR-005). 금액·사진 같은 입력도 차량 화면에 두지 않는다(ARO-F8-AC13). 2차 고도화 이후의 선택 과제로 남긴다(개발 기록 F24) |
| 가족 기록 자연어 검색 | (구상) | 1단계는 규칙·키워드 검색으로 충분하다(장소·날짜·인원 열로 찾기). 2단계 RAG(검색 증강 생성 — 근거 문서를 찾아 답을 만드는 방식)는 데이터량·가족 동의·사람 확인 세 조건이 모두 충족될 때만 다시 판단한다. 평가 지표를 먼저 정해 둔다 — 이 문서에서 처음 정의: ①근거 적중(정답이 있는 기록을 찾아냈는가) ②근거 인용률(답이 근거 기록을 밝혔는가) ③거짓 답 0건(근거 없는 답을 0건으로 유지) |
| 가족 기록 지식 그래프 | (구상) | 인물·장소·연도 관계는 방문 기록 표의 열(장소·시각·가족·인원·차량)로 충분하다(backend/app/models.py). 관계망 구조는 기록이 쌓여 표 검색으로 답이 안 되는 규모가 될 때 다시 판단한다 |
| 멀티에이전트·에이전트 루프 | 불필요 | 도착→스탬프→기록→음성→다음 목표는 순서가 고정된 결정적 흐름이다(TripSession 파이프라인 — ADR-002, TripSessionTest). 오류도 규칙으로 처리한다: 음성 3단 폴백(ADR-007), 주행 상태는 더 제한적 우선(ADR-005), PIN 없는 세션은 전송을 401로 보류(ADR-003·ADR-004 멱등키). 스스로 계획을 세워 도구를 고르는 프로그램이 맡을 일이 없다 |
| 미세조정(모델을 예시 데이터로 다시 학습시키는 방식) | 해당 없음 | 앱·서버·웹 소스에 언어 모델 호출·학습 코드가 없다(코드 전수 확인). 학습시킬 모델이 없으므로 판정 대상 자체가 없다. 모든 문장은 시드 파일에 사람이 쓴 상수로 들어 있다(assets/seed/seed.json) |

### 표의 근거 보강 노트

- 도착 해설·퀴즈: 시드의 해설·퀴즈 문장은 사람이 쓴 상수다. 문장이 화면에 나가려면 검수 전 '초안' 표시를 거치고, 공식 자료 대조를 통과해 플래그가 true로 바뀌는 길만 있다(assets/seed/seed.json, ui/parked/ParkedSteps.kt 주석 규칙).
- 주행 중 음성 비서: 앱의 상호작용은 정차 화면에만 둔다. 음성 편지 카드는 정차 중에만 있고 주행 화면에는 없다(ARO-F5-AC13) — 질문을 받을 화면이 애초에 정차 쪽에만 있다는 뜻이다.
- 가족 기록 검색: 지금 답하는 방식은 표 조회다. 방문 기록은 장소·시각·인원이 열로 담긴 표이므로 키워드·조건 검색으로 예측 가능하게 답한다(backend/app/models.py).
- 지식 그래프: 관계망을 만드는 일은 기록 전체를 다시 짜는 비용이 크다. 지금 규모에서는 표의 열이 같은 질문에 더 빠르고 검증 가능하게 답한다.
- 미세조정: 데이터 준비·학습 절차도 존재하지 않는다. 없는 절차를 문서화하지 않는다 — 이 표 한 줄이 그 판정 전부다.

## 2. 선택 규칙 요약

아로새김은 새 기술 후보를 이 순서로 판단한다.

1. 정답이 하나로 정해지는 일인가. 도착 판정·스탬프·포인트는 정해진 규칙이 답하는 일이다. 답이 하나로 정해진다면 문장을 새로 만드는 방식을 붙이지 않는다.
2. 틀리면 곧바로 피해가 되는 문장인가. 유물 해설·퀴즈는 사실이 바뀌면 역사를 잘못 알려준다. 오류 비용이 이 정도인 자리는 사람이 쓰고 검수하는 길만 남긴다.
3. 순서가 정해진 일인가. 도착→스탬프→기록→음성처럼 단계가 고정된 흐름은 코드가 순서를 정한다. 흐름이 고정이면 스스로 계획을 세우는 프로그램(에이전트)은 필요 없다.
4. 답의 재료가 이미 있는가. 가족 기록은 지금 쌓이는 중이다. 재료(데이터량)와 허락(가족 동의), 확인(사람 검수)이 갖춰지기 전에는 검색으로 답을 만드는 방식(RAG)을 넣지 않는다.
5. 질문이 들어올 자리가 있는가. 주행 중 입력은 구조상 막혀 있다. 질문이 들어올 화면이 없으면 검색 증강을 붙일 자리도 없다.
6. 관계가 표로 해결되는가. 인물·장소·연도는 표의 열 몇 개로 답한다. 관계망 구조는 규모가 커졌을 때의 선택지로만 남긴다.

## 3. 사람 확인(HITL — 사람이 검토하고 승인하는 절차)

### 3-1. 검수 플래그(reviewed)

- 시드의 퀴즈·해설·그때와 지금 문장마다 `reviewed`(검수 여부) 플래그가 붙고, 시드의 현재값은 전부 false(검수 전)다(assets/seed/seed.json).
- 도메인 모델도 같은 필드를 가진다: 퀴즈 `QuizItem.reviewed`, 장소 해설 `narrationReviewed`(android/.../domain/Models.kt, 개발 기록 F19). 검수 전 문장은 화면에 '초안' 꼬리표가 붙는다(ui/parked/ParkedSteps.kt 주석 규칙).
- 검수는 공식 자료 대조로 사람이 한다. 시드 주석이 길을 정한다: "퀴즈·해설 문장은 초안이며 공식 자료로 검수한 뒤 reviewed=true로 바꿀 것", "출처 문장을 그대로 붙여 넣지 말 것"(assets/seed/seed.json 머리 주석).
- 학설이 갈리는 유물은 단정하지 않는다 — 대릉원·첨성대 해설은 학설 문구와 함께 검수 전 상태로 들어가 있다(assets/seed/seed.json).

### 3-2. 보호자 동의

- 미성년 구성원이 있는 가족이 보호자 동의를 아직 기록하지 않았으면, 서버는 그 가족의 사진 업로드를 403(guardian_consent_required)으로 거부한다. 동의 기록 후에는 같은 요청이 성공한다(docs/spec/ac/f7_family.json ARO-F7-AC08, 서버 시험 test_minor_photo_requires_guardian_consent).
- 사진이 없는 기억 기록은 보호자 동의와 무관하게 허용된다(ARO-F7-AC09).
- 이 규칙은 가족 계승 요구에 따라 코드에 들어갔다(개발 기록 F21).

### 3-3. 영수증 인증(AI 없음 — 규칙 판정)

- 영수증 판정은 언어 모델이 아니라 고정된 규칙 순서가 한다: 금액 → 중복 → 방문 연계 → 대기 → 한도(backend/app/services/points.py, ADR-011).
- 사진·금액·제휴처·날짜가 규칙을 통과해야 적립되고, 사진 해시가 같은 재제출은 거부된다(ARO-F8-AC01·AC07).
- 같은 제휴처·같은 날 두 번째 영수증은 확인 대기(pending)로 저장하고 적립은 0으로 둔다 — 규칙이 넘긴 판정을 사람 확인 자리에 남긴다(ARO-F8-AC08, backend/app/services/points.py).
- 모든 혜택 표기는 "포인트 캐시백(예시)"과 시뮬레이션 표시를 붙인다(ARO-F8-AC12).

### 3-4. 음성 원칙

- 안내 음성·음성 편지는 사람이 미리 준비한 오디오를 재생하는 것뿐이다. 재생 순서는 사전 제작 오디오 → 차량 음성 합성 → 안드로이드 기본 음성의 3단 체인이다(ARO-F5-AC01, ADR-007).
- 떠난 가족의 목소리를 AI로 다시 만들지 않는다. 음성 편지는 재생 전용이고, 합성으로 목소리를 새로 만드는 길은 없다(개발 기록 F40, ADR-007).
- 오디오 파일이 없으면 앱은 재생을 생략하고 "예시(음성 준비 중)" 안내를 보인다 — 없는 것을 있는 것처럼 말하지 않는다(ARO-F5-AC09).

## 4. 판정을 바꾸는 절차

- (구상) 항목을 다시 판단할 때는 표의 조건부터 확인한다. 조건이 충족됐는지는 코드·데이터·동의 기록으로 확인하고, 충족됐으면 새 설계 결정(ADR)을 하나 추가한 뒤 이 표의 판정을 바꾼다.
- 평가 지표는 조건 확인보다 먼저다. 가족 기록 검색을 넣기로 했다면 근거 적중·근거 인용률·거짓 답 0건 세 지표의 측정 방법을 정한 뒤에 시험을 만든다.
- 판정을 바꿔도 사람 확인 절차(3절)는 남긴다. 생성형 기능을 넣는 순간에도 검수 플래그·보호자 동의·규칙 우선 원칙은 그대로 유지한다.
