# F9 오프라인·대체 구현

## 1. 한눈에 보기

서버와 SDK가 불안정해도 앱이 끝까지 동작하게 만드는 기능들입니다.
차량 SDK 호출은 7개 포트(인터페이스) 뒤로만 감싸서 쓰고, 시작 때 초기화 콜백을 기다리지 않고 그 순간 확인 가능한 값만으로 구현을 선택합니다(콜드 부팅 연속 2회 실측 — 강제 종료 0건, docs/ADR.md ADR-008).
경로 안내·음성 안내 포트는 대체 구현으로 기동한 뒤 SDK 초기화가 늦게 성공하면 차량 연동으로 전환하고 되돌아가지 않습니다. 전송 대기열은 주기 재시도 없이 도착 1건당 1회 전송을 시도하고, PIN은 파일에 남기지 않습니다.
수용 기준 12건 중 [확인] 1·[코드 확인] 8·(설계) 3입니다.
주기 재시도 없음(AC07)은 (설계)에서 [코드 확인]으로 갱신된 항목입니다 — 재시도 루프가 없음을 직접 겨냥한 단위 시험 2건이 이를 실현했습니다(이 문서 6절·7절).
아직 미확인인 것: 진단 화면의 구현 표시(AC04)·빈 큐 0건(AC09)의 단위 시험·실측이 없어 (설계)로 남아 있습니다(AC09 note — 이 분기를 직접 겨냥한 단위 시험 이름을 찾지 못함).

## 2. 목적과 범위

| 요소 | 내용 |
|---|---|
| 포함 | 7개 포트(주행 상태·경로 안내·도착 감지·음성 안내·차량 정보·차량 신호 조회·음성 편지 재생) 뒤의 SDK 호출 은닉, 시작 시 즉시 구현 선택과 늦은 초기화 성공 시의 일방향 전환, 진단 화면의 '구현: ○○' 표시, 차량 신호를 못 읽었을 때의 가짜 값 금지, 도착 1건당 전송 1회 시도, 실패 건에서 멈추는 FIFO 순서 보장, PIN의 헤더 전용 사용과 파일 비저장, 내장 데이터(코스·스탬프북·맛집)로의 서버 없음 흡수 |
| 제외 | 서버의 방문 저장·같은 분 멱등 판정(F7 문서), PIN 거절 표시의 세부(F6 문서), 음성 3단 체인의 내용(F5 문서), 주행·정차 판정(F2 문서), 도착 판정 규칙(F1 문서) |
| 가정 | 확인되지 않은 SDK 동작을 사실처럼 구현하지 않는다는 원칙(docs/ADR.md ADR-014 — 개발 기록 F1~F12의 AAR·Maven 실측 기반). 차량 신호를 못 읽으면 가짜 값을 채우지 않고 빈 값으로 남겨 문장을 숨깁니다(AC05). 로컬 저장은 Room이 아니라 단일 JSON 파일 두 개로 충분하다(docs/ADR.md ADR-013) |
| 경계 | 멱등키는 placeId|courseId|방문 시각(분 단위)|familyCode이며 서버의 같은-분 판정(F7 문서)과 이중 방어를 이룹니다(docs/ADR.md ADR-004). 전송 대기열은 스스로 주기 재시도하지 않습니다(AC07 — 전송 호출 지점이 도착 처리 한 곳뿐이라는 소스 전수 검색 기록에 재시도 루프 없음 단위 시험 2건이 더해졌습니다). 서버 호출 실패는 흡수되고 주행 흐름을 막지 않습니다(AC12) |

## 5. 입력→출력 예시

**콜드 스타트 즉시 선택(AC02).** 콜드 스타트에서 내비게이션 SDK 초기화 콜백이 아직 안 온 상태로 앱이 시작되면 경로 안내 포트는 대기 없이 즉시 대체 구현으로 기동하고, 이후 콜백이 오면 자동으로 차량 연동으로 전환합니다. 콜드 부팅 직후 연속 실행 2회 실측에서 강제 종료가 0건이었습니다 — docs/ADR.md ADR-008의 결과(개발 기록 F61의 해소 실측을 이어받은 항목).

**일방향 전환(AC03).** 대체 구현으로 기동한 뒤 3초 뒤 차량 SDK 초기화 성공 신호가 오면 차량 연동 구현으로 전환하고, 전환 뒤 SDK 신호가 다시 실패해도 대체로 되돌아가지 않습니다 — 단위 테스트 SwitchableRouteServiceTest `3_재전환은 일방향 — 두 번째 switchTo는 전부 무시된다`, SwitchableNarratorTest `전환은 일방향 - ready가 false로 되돌아가도 Pleos를 유지한다`.

**전송 대기열(AC06·AC08).** 국립경주박물관 도착 스탬프 기록 시 방문 기록이 대기열에 1건 적재되고 곧바로 전송 1회를 시도합니다. 큐에 3건이 있는 상태에서 첫 건이 실패하면 첫 건과 나머지 2건 모두 순서가 바뀌지 않은 채 큐에 남습니다 — 단위 테스트 VisitQueueTest `2_flush 성공시 큐가 비우고 전송 건수를 돌려준다`, `3_flush 실패시 항목이 큐에 유지된다`, `5_flush는 FIFO 순서를 지키고 부분 실패 후 이어서 재전송한다`.

**PIN과 내장 데이터(AC10·AC11·AC12).** 세션 PIN이 있으면 전송 요청 헤더(X-Family-Pin)에 실리고, 큐 파일(JSON)에는 장소·시각 등만 있고 PIN 문자열은 없습니다. 서버가 없어도 내장 데이터로 여정이 끝까지 이어지고 서버 호출 실패는 흡수됩니다 — 단위 테스트 VisitQueueTest(`6_pin 공급자의 세션 PIN 이 X-Family-Pin 값으로 전달된다`, `7_enqueue 로 받은 PIN 은 파일에 저장되지 않고 전송에만 쓰인다`), SeedRepositoryTest missingStampBookAndPartners_defaultToEmptyLists, TripSessionTest `8_routeService_호출 실패시 주행은 유지되고 한 줄 안내만 남는다`.

## 6. 오류·예외 처리

- 포트 선택을 초기화 콜백까지 기다리던 구조가 릴리스 첫 실행에서 영구 멈춤(ANR)을 일으켰고, 동기 즉시 판정 + 늦은 초기화 성공 시 일방향 업그레이드로 고쳤습니다. 콜드 부팅 직후 첫 실행 2회 연속에서 강제 종료 0건을 실측했습니다 — docs/ADR.md ADR-008, 개발 기록 F61.
- 차량 신호 조회가 실패하면 가짜 값을 채우지 않고 tripKm·partySize를 null로 남깁니다 — 단위 테스트 TripSessionTest `10_tripSignals_읽기 실패시 tripKm과 partySize는 null로 남는다`(AC05), docs/ARCHITECTURE.md 6절 U11 표.
- 전송 중 실패는 그 항목에서 멈춰 순서를 지키고, 재전송은 다음 도착 시점에 이어서 합니다 — 단위 테스트 VisitQueueTest(위 5절). 재시도 루프는 없습니다(AC07의 [코드 확인] 근거) — 단위 테스트 VisitQueueTest `10_전송 실패 후 재시도 루프는 없다 — flush 1회당 시도도 1회다`, TripSessionTest `16_도착 1건당 flush는 1회만 호출된다 — 실패해도 재시도 루프는 없다`, 개발 기록 F82(공회전 폴링 없음 실측).
- 전송용 PIN은 메모리에만 잠깐 두고 큐 파일에 적지 않습니다 — 단위 테스트 VisitQueueTest `7_enqueue 로 받은 PIN 은 파일에 저장되지 않고 전송에만 쓰인다`(AC11), PIN 거절 시의 재전송 중단은 [F6 문서](F6_가족코드PIN세션.md) 6절.
- 서버 호출 실패는 흡수되고 주행 흐름을 막지 않습니다(경로 요청 실패 시 주행 유지·한 줄 안내) — 단위 테스트 TripSessionTest `8_routeService_호출 실패시 주행은 유지되고 한 줄 안내만 남는다`(AC12).
- 릴리스 빌드의 평문 HTTP 차단 사례: debug 변형 매니페스트만 cleartext를 허용해 릴리스 앱의 서버 호출이 전부 클라이언트에서 막혔던 과거가 있고, network_security_config.xml(10.0.2.2·localhost만 예외) 신설로 해소됐습니다 — 개발 기록 F71.
- VisitQueue 시험의 가짜 구현이 실패 시도까지 기록해 단언과 어긋났던 과거가 있었고 구현 자체는 사양대로(실패 시 즉시 중단·순서 보장)였습니다 — 개발 기록 F33(시험 픽스처 버그 수정).
