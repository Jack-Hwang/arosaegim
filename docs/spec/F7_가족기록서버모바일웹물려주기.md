# F7 가족 기록 서버·모바일 웹·물려주기

## 1. 한눈에 보기

가족 기록의 주인은 '가족'이고 서버가 발급·보안 가드·저장·내보내기를 담당하는 기능입니다.
가족 코드 8자리·PIN 6자리 발급(평문은 응답 한 번만), PIN 5회 실패 10분 잠금(429), 기기당 하루 1회 발급 제한, 같은 분 안의 방문 멱등, 사진 EXIF 제거, 미성년 보호자 동의 검사, ZIP 내보내기, 코스 주행 식별자 기준의 거리 중복 제거, 물려주기 지정(owner → 이어받을 사람)이 들어 있습니다.
수용 기준 15건 중 [코드 확인] 14·(설계) 1입니다.
아직 미확인인 것: 차량 앱에서 코드·PIN 입력 → 도착 → 서버 visits 행까지의 전체 경로 실측(개발 기록 Q29), PIN 없는 세션에서 물려주기 안내의 화면 실측(개발 기록 Q20), 발급 경로의 실측(AC01 — (설계))입니다.

## 2. 목적과 범위

| 요소 | 내용 |
|---|---|
| 포함 | 가족 코드·PIN 발급(8자리·6자리 — 응답 한 번에만 평문), 기기 식별값당 하루 1회 발급 제한(429 device_limit), PIN 잠금(5회 실패 → 10분 429 family_locked·코드 재발급만 예외), PIN 헤더 검증(401 pin_required), 방문 멱등(같은 분 같은 장소·코스 — 같은 스탬프 번호), 사진 EXIF 제거 후 저장, 미성년 구성원의 사진 업로드 보호자 동의 검사(403), 가족 데이터 ZIP 내보내기(timeline.json·README.html·photos), 가족 누적 거리(course_run_id 중복 제거), 물려주기 지정·재지정·권한 검사(403 not_owner), 차량 완주 질문 정책과 PIN 없는 세션의 안내 전환 |
| 제외 | 차량 화면의 "그때와 지금" 표시(F4 문서), 영수증·포인트 규칙(F8 문서), 차 안 전송 대기열의 동작(F6·F9 문서), 모바일 웹 화면의 구성(웹 화면 1~7), 방문 전송 필드의 앱 쪽 계약(VisitPayloadContract — [F9 문서](F9_오프라인대체구현.md)의 전송 영역) |
| 가정 | PIN은 솔트를 붙은 SHA-256 해시(salt$digest)로만 저장하고 비교는 상수 시간(hmac.compare_digest)입니다(docs/ADR.md ADR-010). 기록의 주인은 가족이라 같은 코드로 다른 차·렌터카에서도 이어집니다(docs/ARCHITECTURE.md 1절). 차량에는 가족 기록을 오래 두지 않는다 — 내보내기·물려주기가 그 대체 수단입니다 |
| 경계 | 발급·잠금·멱등·저장·내보내기는 서버, 완주 질문을 보여줄지의 판정은 차량 앱의 순수 정책 클래스입니다. PIN 평문은 발급 응답 한 번 뒤로는 응답에 다시 나오지 않습니다(AC01 io). 사진 이름표는 비율 좌표이고 자동 인식은 하지 않습니다(B5 — docs/TRACEABILITY.md 1절) |

## 3. 입력·출력·상태

| 구분 | 항목 | 내용 |
|---|---|---|
| 입력 | 가족 생성 요청 | 기기 식별값(device_token) 포함 — 하루 1회 제한 대상 |
| 입력 | 가족 데이터 조회 | X-Family-Code + X-Family-Pin 헤더(헤더 없으면 401 pin_required) |
| 입력 | 방문 전송 | 스네이크 케이스 필드(place_id·course_id·visited_at·vehicle_label 등) |
| 입력 | 사진 업로드 | EXIF 포함 JPEG, 미성년 구성원이 있는 가족은 보호자 동의 검사 대상 |
| 입력 | 물려주기 요청 | owner PIN 헤더 + 대상 구성원(heir) 지정 |
| 출력 | 응답 코드 | 200 / 400 / 401(invalid_pin·pin_required) / 403(guardian_consent_required·not_owner) / 429(device_limit·family_locked) |
| 출력 | 발급 응답 | 가족 코드 8자리 + PIN 6자리(평문 1회) |
| 출력 | 내보내기 | ZIP 1개(timeline.json·README.html·photos 폴더) |
| 출력 | 지표 | 가족 누적 거리(같은 날 같은 코스 주행은 한 번만 더함) |
| 상태 | 잠금·멱등 | locked_until(미래 시각으로 기록), 멱등 키(가족·장소·코스·방문 시각 분 단위), heir 지정(1명 — 재지정 시 이전 지정자는 일반 구성원으로 복귀) |

## 4. 수용 기준

수용 기준은 EARS(요구를 다섯 모양의 한 문장으로 쓰는 방법)로 쓰여 있고, 아래 표는 정본 JSON에서 생성했습니다.

|---|---|---|---|---|

| AC02 | 금지 | 같은 기기 식별값으로 하루에 두 번째 가족 코드를 발급받으려 하면 서버는 429(device_limit)로 거부합니다. | 서버 시험 | [코드 확인] |
| AC03 | 금지 | PIN을 5회 연속 틀리면 서버는 10분간 그 가족의 모든 요청을 429(family_locked)로 막고, 그 안에는 올바른 PIN을 보내도 막습니다. | 서버 시험 | [코드 확인] |
| AC04 | 상태 | 가족이 PIN 잠금 상태인 동안 서버는 코드 재발급 요청만 예외로 받아들이고, 그 외 요청은 모두 429로 거부합니다. | 코드 확인 | [코드 확인] |
| AC05 | 금지 | X-Family-Pin 헤더 없이 가족 데이터를 조회하면 서버는 401(pin_required)로 거부합니다. | 서버 시험 | [코드 확인] |

| AC07 | 항상 | 서버는 저장하는 모든 사진에서 EXIF(위치·시각 등 메타데이터)를 제거하고 다시 저장합니다. | 서버 시험 | [코드 확인] |
| AC08 | 금지 | 가족에 보호자 동의를 아직 받지 못한 미성년 구성원이 있으면 서버는 그 가족의 사진 업로드를 403(guardian_consent_required)으로 거부합니다. | 서버 시험 | [코드 확인] |

| AC10 | 사건 | 가족 데이터 내보내기를 요청하면 서버는 timeline.json·README.html·photos 폴더가 든 ZIP 파일 하나를 돌려줍니다. | 서버 시험 | [코드 확인] |

| AC14 | 사건 | 차량 화면에서 코스를 완주한 직후(주행 중이 아니고, 이어받을 사람이 아직 없고, 지정할 구성원이 있을 때) 앱은 이어받을 사람을 묻는 질문을 보여줍니다. | 단위 시험 | [코드 확인] |

표의 '확인 방법'은 정본의 verify.kind를 한국어로 옮긴 것입니다 — 단위 시험(앱 JVM 테스트), 서버 시험(backend pytest), 에뮬레이터 실측(Pleos Connect 에뮬레이터 실행 기록), 코드 확인(소스 코드 근거).
상태 어휘는 정본과 같습니다 — [확인]·[일부 확인]·[코드 확인]·[실패]는 시험·실측까지 끝난 정도를, (설계)는 코드로 구현됐으나 화면 실측이 남은 항목을 뜻합니다.

## 5. 입력→출력 예시

**PIN 잠금(AC03·AC04).** 잘못된 PIN으로 5회 연속 조회하면 매번 401 invalid_pin으로 답하고, 이후에는 올바른 PIN을 보내도 429 family_locked로 막습니다. 잠금 상태에서는 코드 재발급 요청만 PIN 검증을 허용하고 그 외 요청은 모두 429입니다 — 서버 시험 test_pin_locks_after_five_failures, 소스 backend/app/config.py(PIN_LOCK_ATTEMPTS=5·PIN_LOCK_MINUTES=10).

**방문 멱등(AC06).** 14:30:00에 보낸 방문을 14:30:59에 다시 보내면 같은 분이라 새 방문을 만들지 않고 같은 스탬프 번호 1을 돌려줍니다. 14:31:00(다른 분)에 보내면 서로 다른 방문이 되어 스탬프 번호가 1→2로 늘어납니다 — 서버 시험 test_same_minute_is_idempotent, test_different_minute_creates_new_visit.

**누적 거리 중복 제거(AC11).** 같은 날 같은 코스 주행(course_run_id 동일)의 두 장소 방문에 각각 132.5km가 기록돼도 가족 누적 거리는 132.5km입니다(한 번만 더함). 다음 날 같은 코스를 100.0km로 다시 주행하면 232.5km로 늘어납니다 — 서버 시험 test_metrics_total_trip_km_dedup_same_course_run.

**물려주기(AC12·AC13·AC14·AC15).** owner가 다른 구성원을 이어받을 사람으로 지정하면 역할이 바뾸고 재지정 시 이전 지정자는 일반 구성원으로 복귀합니다. owner가 아닌 PIN은 403 not_owner, 헤더 없음은 401 pin_required입니다. 차량 화면은 완주 직후(비주행·미지정·구성원 있음)에만 질문을 보여주고, PIN이 없으면 서버 호출 없이 '스마트폰의 가족 관리에서 정해 주세요' 안내로 전환합니다 — 서버 시험 test_heir_and_handover_flow 등, 단위 테스트는 이어받을 사람 질문·PIN 안내 전환 단위 테스트.

## 6. 오류·예외 처리

- PIN은 평문이 아니라 세트별 무작위 솔트를 붙인 SHA-256 해시(salt$digest)로만 저장하고 비교는 hmac.compare_digest로 합니다. 이 해시 경로의 직접 단위 시험은 없고 전 API 시험이 인증 경로를 통과하며 간접 검증합니다 — docs/ADR.md ADR-010, docs/TRACEABILITY.md 3절.
- 잠금 시각(locked_until)은 미래 시각으로 기록되며 이를 검증하는 서버 시험이 있습니다 — test_pin_lock_records_locked_until_in_future, 소스 backend/app/security.py(_fail_pin·_is_locked).
- 구성원이 없는 상태에서 물려주기 지정을 요청하면 과거에는 500이 났고 400으로 고쳤습니다 — 개발 기록 2026-11-12 섹션(서버 S1~S3), 서버 시험 test_heir_owner_auth_failure_is_403.
- 보호자 동의는 사진 업로드에만 걸고 사진이 없는 기억 기록은 동의와 무관하게 허용합니다 — 서버 시험 test_minor_photo_requires_guardian_consent(AC08·AC09 두 케이스를 같은 시험 파일이 담당).
- 사진은 저장 전에 EXIF를 제거해 다시 저장하므로 위치·시각 메타데이터가 남지 않습니다 — 서버 시험 test_exif_is_stripped, 소스 backend/app/services/photos.py.
- 차량 앱 쪽 완주 질문 정책은 주행 중에는 묻지 않고, 이미 지정돼 있으면 다시 묻지 않으며, PIN이 없으면 서버 호출을 시도하지 않고 안내 카드로 전환합니다 — 단위 테스트 이어받을 사람 질문 단위 테스트("완주 비주행 미지정 구성원있음이면 물어본다", "주행 중에는 물어보지 않는다")·PIN 안내 전환 단위 테스트(2케이스), 개발 기록 Q20(403 안내의 실측 대기).
