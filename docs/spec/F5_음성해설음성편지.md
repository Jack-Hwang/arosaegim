# F5 음성 해설·음성 편지

## 1. 한눈에 보기

안내 음성과 음성 편지의 재생 기능입니다. 안내 음성은 사전 제작 오디오 → 차량 음성 합성(Pleos) → 안드로이드 기본 음성 순서의 3단 체인으로 시도하도록 설계됐고, 전환은 한 방향으로 되돌아가지 않습니다.
전환 규약(초기화 전 대체 사용·늦은 성공 시 전환·정직한 준비 상태 답변)은 단위 시험으로 검증됐고, 음성 편지 카드는 정차 화면에만 둡니다.
수용 기준 11건 중 [코드 확인] 3·[실패] 1·(설계) 7입니다.
아직 미확인인 것: 이 에뮬레이터에서는 안드로이드 기본 음성 초기화와 차량 음성 합성 초기화 확인이 모두 실패해 두 합성 경로 모두 소리가 나지 않고(AC05 — [실패]), 정본은 원인이 아직 확정되지 않았다고 기록합니다. 소리 청취 실측과 음성 편지 재생 화면 실측이 남아 있습니다.

## 2. 목적과 범위

| 요소 | 내용 |
|---|---|
| 포함 | 3단 체인(사전 제작 오디오 → Pleos 합성 → 안드로이드 기본 음성), SwitchableNarrator 전환 규약(onReady 전 대체 즉시 사용·늦은 성공 시 일방향 전환), isAvailable의 정직한 답변, 음성 편지 카드(정차 전용·재생 버튼·가려지면 즉시 정지), 오디오 포커스 처리(상실·일시 상실 정지, 낮추기는 계속) |
| 제외 | 서버 음성 합성 모드(SDK Mode SERVER — 미사용), 녹음 기능(로드맵), 고인의 목소리를 만드는 것(금지 원칙 — 시드 voice_letter_demo 규정), 음성 편지 시드 데이터의 상세(F3·F9의 시드 문서 영역), 도착 문장의 문구 내용(F1 문서 파이프라인) |
| 가정 | 오디오 파일이 없으면 재생을 생략합니다(가짜 금지 — docs/ADR.md ADR-007). TTS의 onDone은 누락될 수 있다는 가정으로 speak 대기에 5초 타임아웃을 둡니다(개발 기록 Q4 — docs/ARCHITECTURE.md 8절) |
| 경계 | 음성 편지는 시드의 예시 1건(letter-demo-1)이고 서버도 같은 예시를 돌려줍니다. 음성 편지 폴백 표시의 진단 규칙은 [F9 문서](F9_오프라인대체구현.md)를 따릅니다. 예시 오디오 파일(letter_demo.wav)은 데모용 일반 합성 음성이며 고인 목소리 합성 금지 원칙과 무관합니다(개발 기록 F64) |

## 3. 입력·출력·상태

| 구분 | 항목 | 내용 |
|---|---|---|
| 입력 | speak 요청 | 도착 문장 등의 낭독 요청(TripSession 파이프라인 5단계 — 스탬프가 등록된 경우만) |
| 입력 | 초기화 콜백 | Pleos TTS의 onReady 이벤트 — 늦게 와도 전환하고 되돌아가지 않습니다(AC03) |
| 입력 | 포커스 이벤트 | 오디오 포커스 상실·일시 상실(즉시 정지), 낮추기 요청(계속 재생 — AC10) |
| 입력 | 재생 버튼 | 음성 편지 카드의 '재생' 클릭 — 자동재생 없음(AC06) |
| 입력 | 생명주기 | 정차 화면이 가려짐(onPause — 주행 전환 포함) — 재생 중인 음성 편지를 즉시 멈춤(AC08) |
| 출력 | 음성 | 활성 구현의 재생(사전 제작 오디오·Pleos 합성·Android 합성 중 하나) |
| 출력 | 문구 | 재생 중 버튼 글자 '재생 중…', 재생 실패 시 '예시(음성 준비 중)'(parked_voice_letter_unavailable) |
| 출력 | 준비 상태 | isAvailable — 현재 활성 구현이 실제로 준비됐는지를 그대로 답하고 꾸미지 않습니다(AC04) |
| 상태 | 활성 구현 | SwitchableNarrator — 대체에서 Pleos로 일방향 전환, false로 되돌아가도 유지(AC03) |
| 상태 | 편지 데이터 | 시드의 단일 예시 객체 1건(letter-demo-1 — gj-museum 묶음·AC06 io) |

## 4. 수용 기준

수용 기준은 EARS(요구를 다섯 모양의 한 문장으로 쓰는 방법)로 쓰여 있고, 아래 표는 정본 JSON에서 생성했습니다.

| 번호 | 유형 | 수용 기준 | 확인 방법 | 상태 |
|---|---|---|---|---|
| AC01 | 항상 | 앱은 안내 음성을 사전 제작 오디오 → 차량 음성 합성(Pleos) → 안드로이드 기본 음성 순서의 3단 체인으로 시도하도록 설계돼 있습니다. | 코드 확인 | (설계) |
| AC02 | 금지 | 차량 음성 합성(Pleos)의 초기화 확인이 아직 안 된 상태에서 문장을 말해야 하면 앱은 기다리지 않고 안드로이드 기본 음성으로 즉시 말합니다. | 단위 시험 | [코드 확인] |
| AC03 | 사건 | 차량 음성 합성의 초기화 확인이 늦게라도 성공하면 앱은 그 다음부터 안드로이드 기본 음성 대신 차량 음성 합성으로 바꿔 말합니다. 이 전환은 한 방향이라 되돌아가지 않습니다. | 단위 시험 | [코드 확인] |
| AC04 | 항상 | 지금 안내 음성을 쓸 수 있는지 묻는 질문에 앱은 현재 활성 구현이 실제로 준비됐는지를 그대로 답하고 꾸미지 않습니다. | 단위 시험 | [코드 확인] |
| AC05 | 금지 | 에뮬레이터 실측에서 안드로이드 기본 음성 초기화와 차량 음성 합성 초기화 확인이 모두 실패해, 지금은 두 합성 경로 모두 소리가 나지 않습니다. 원인은 아직 확정되지 않았습니다. | 에뮬레이터 실측 | [실패] |
| AC06 | 사건 | 가족이 음성 편지 재생 버튼을 누르면 앱은 그 순간부터 사전 제작 음성 편지 재생을 시작합니다(자동재생 없음). | 코드 확인 | (설계) |
| AC07 | 금지 | 음성 편지 파일을 쓸 수 없거나 재생이 실패하면 앱은 '예시(음성 준비 중)' 글자 안내로 바꿔 보여줍니다. | 코드 확인 | (설계) |
| AC08 | 사건 | 정차 화면이 가려지면(주행 전환이나 다른 화면으로 전환) 앱은 재생 중인 음성 편지를 즉시 멈춥니다. | 코드 확인 | (설계) |
| AC09 | 금지 | 다른 소리가 오디오 포커스를 완전히 또는 일시적으로 가져가면 앱은 재생 중인 안내 음성·음성 편지를 즉시 멈춥니다. | 코드 확인 | (설계) |
| AC10 | 선택 | 다른 소리가 낮추기만 요청하는 경우(소리를 줄여도 되는 상황) 앱은 재생을 멈추지 않고 계속합니다. | 코드 확인 | (설계) |
| AC11 | 상태 | 차가 정차한 상태인 동안에만 앱은 음성 편지 카드를 화면에 둡니다. 주행 화면에는 이 카드 자체가 없습니다. | 코드 확인 | (설계) |

상태 분포: [코드 확인] 3건 · [실패] 1건 · (설계) 7건.

정본: [docs/spec/ac/f5_voice.json](ac/f5_voice.json)

표의 '확인 방법'은 정본의 verify.kind를 한국어로 옮긴 것입니다 — 단위 시험(앱 JVM 테스트), 서버 시험(backend pytest), 에뮬레이터 실측(Pleos Connect 에뮬레이터 실행 기록), 코드 확인(소스 코드 근거).
상태 어휘는 정본과 같습니다 — [확인]·[일부 확인]·[코드 확인]·[실패]는 시험·실측까지 끝난 정도를, (설계)는 코드로 구현됐으나 화면 실측이 남은 항목을 뜻합니다.

## 5. 입력→출력 예시

**초기화 전 낭독(AC02).** onReady=false 상태에서 speak("안녕")를 호출하면 대체(안드로이드 기본 음성 자리)가 즉시 말을 시작하고 기다리지 않습니다 — 단위 테스트 SwitchableNarratorTest `onReady 전에는 대체(Android TTS 자리)로 말한다 - 블로킹 없이 즉시 기동`.

**늦은 초기화 성공(AC03).** onReady가 늦게 true로 바뀌면 그 다음 speak부터 차량 음성 합성(Pleos)이 담당하고, 그 뒤 onReady가 false로 되돌아가도 Pleos를 유지합니다 — 단위 테스트 `onReady 지연 확인 후에는 Pleos로 말한다`, `전환은 일방향 - ready가 false로 되돌아가도 Pleos를 유지한다`.

**에뮬레이터 실패(AC05).** 진단 화면의 안내 음성 재생 버튼(스모크 U6)을 누른 결과 소리가 나지 않았고 두 합성 경로 모두 실패로 끝났습니다 — 안드로이드 기본 음성 초기화 실패와 Pleos onReady 미수신(개발 기록 U6·F54). 정본은 원인이 아직 확정되지 않았다고 기록하며, 원인 조사는 Q16(안드로이드 TTS)·Q17(Pleos onReady)으로 남아 있습니다.

**재생 버튼(AC06·AC07).** gj-museum 정차 화면에서 '재생' 버튼을 누르면 letter-demo-1 음성 재생이 시작되고 버튼 글자가 '재생 중…'으로 바뀝니다. 재생이 실패하면(파일을 쓸 수 없음) '예시(음성 준비 중)' 글자 안내로 바꿔 보여줍니다 — 소스 ThenNowExtras.kt(VoiceLetterCard), strings.xml(parked_voice_letter_unavailable).

아래는 정본 JSON의 io 필드를 요약 없이 인용한 것입니다.

| AC | 입력 | 출력 |

## 6. 오류·예외 처리

- 안드로이드 TTS 초기화 실패·Pleos onReady 미수신이 겹치면 안내 음성이 나지 않습니다. 환경 한계 가능성이 기록돼 있고(개발 기록 F54), 정본 AC05가 원인 미확정을 [실패]로 남깁니다.
- Pleos TTS는 initialize 전에 addEventListener를 호출하면 UninitializedPropertyAccessException이 납니다. 순서를 뒤집어(initialize 먼저) 수정했고 초기화는 성공했습니다 — 개발 기록 F30.
- onDone이 누락될 수 있다는 가정으로 speak 대기에 5초 타임아웃을 뒀습니다 — docs/ARCHITECTURE.md 8절(TTS onDone 누락 대비), 개발 기록 Q4.
- 음성 편지 재생이 실패하면 '예시(음성 준비 중)' 안내로 바꿔 보여줍니다 — strings.xml(parked_voice_letter_unavailable), 소스 app/src/main/java/app/arosaegim/ui/parked/ThenNowExtras.kt(VoiceLetterCard).
- 정차 화면이 가려지면(주행 전환 포함) ParkedActivity의 onPause에서 재생을 즉시 멈춥니다 — 소스 app/src/main/java/app/arosaegim/ui/parked/ParkedActivity.kt(onPause), docs/ARCHITECTURE.md 7절.
- 오디오 포커스가 상실·일시 상실되면 즉시 멈추고, 낮추기 요청(AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK)은 미처리로 계속 재생합니다 — 소스 pleos/PleosVoiceLetterPlayer.kt(focusListener)·fallback/AssetAudioNarrator.kt·pleos/PleosTtsNarrator.kt.
- 예시 오디오 파일이 없으면 재생을 생략합니다(가짜 금지). assets/seed/letter_demo.ogg를 넣는 순간 재생 포트가 자동 활성화된다가 발주자 준비 조건으로 기록돼 있습니다 — 개발 기록 Q14·F64.
