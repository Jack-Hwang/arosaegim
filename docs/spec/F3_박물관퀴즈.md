# F3 박물관 퀴즈

## 1. 한눈에 보기

정차 화면의 퀴즈 단계입니다. 경주 코스 3곳(국립경주박물관·대릉원·첨성대)마다 퀴즈 2문항씩, 전체 6문항을 APK에 내장했고 지금 6문항 전부가 검수 전(초안) 상태입니다.
검수 전 문항에는 '초안' 꼬리표가 붙고, 이 표시가 화면에 나오는 것까지 에뮬레이터 실측됐습니다(AC07 — [확인], 실측 화면 8).
정답·오답 안내 문장, 빈 퀴즈 안내, 마지막 문항 이후의 단계 전환, 주행 전환 중의 진행 보존이 나머지 내용입니다.
수용 기준 10건 중 [확인] 1·[코드 확인] 4·(설계) 5입니다.
아직 미확인인 것: 채점 문장(AC01·AC02)·빈 퀴즈 안내(AC08)·단계 전환(AC09)·진행 보존(AC10)은 코드 근거만 있고 화면 실측 기록이 없습니다.

## 2. 목적과 범위

| 요소 | 내용 |
|---|---|
| 포함 | 시드 퀴즈 로드(장소별 2문항·전체 6문항), 정답 안내('정답이에요!' + 해설)·오답 안내('정답: …'), 검수 전 문항의 '초안' 꼬리표, 빈 퀴즈 안내, 마지막 문항 후 '그때와 지금' 단계 전환, 주행 전환 중 문항·보기·채점 결과 보존(QuizStateHolder), 주행 중 정차 화면 전환 금지와 세션 없음 전환 보류(F2 라우팅 규칙의 재사용) |
| 제외 | 퀴즈 정답률·점수의 집계(구현 없음), 문항 검수 워크플로와 reviewed=true 문항(현재 0건), 문항 추가·편집 화면, 정차 화면의 다른 단계(스탬프 카드·그때와 지금 — F4 문서), 음성 안내(F5 문서) |
| 가정 | 문항 내용은 APK 내장 시드(assets/seed/seed.json)에서 파싱되며 전 문항이 reviewed=false입니다(단위 테스트 SeedRepositoryTest). 문항당 보기는 3개다(AC02 io 기준). 퀴즈가 열리는 조건은 정차 + 가족 세션 존재입니다(AC04·AC05) |
| 경계 | 화면 전환 조건 자체는 F2 문서의 라우팅 규칙입니다(ModeRouterResolveTest 공유). 퀴즈 화면 코드는 ParkedScreen과 ParkedSteps로 나뉘어 있고 단계 전환은 ParkedSteps의 QuizStep(stepIndex)이 담당합니다. 퀴즈 상태는 프로세스 수명 싱글톤에 두며 장소가 바뀌었을 때만 초기화합니다(docs/ARCHITECTURE.md 3절·9절 Q13) |

## 3. 입력·출력·상태

| 구분 | 항목 | 내용 |
|---|---|---|
| 입력 | 장소·세션 | 도착한 장소(현재 목표)와 정차 상태·가족 세션 존재 여부 — 퀴즈 탭이 열리는 조건 |
| 입력 | 보기 선택 | 문항당 3개 보기 중 탭 하나 — 소스 app/src/main/java/app/arosaegim/ui/parked/ParkedSteps.kt(QuizStep) |
| 출력 | 채점 문장 | 정답 '정답이에요!' + 해설, 오답 '정답: (정답 보기 문장)' — strings.xml(parked_quiz_correct·parked_quiz_wrong) |
| 출력 | 꼬리표 | 검수 전 문항 옆 '초안' 표시 — 실측 화면 8(2026-11-12 캡처: 문항 머리에 '1/2'와 '초안' 표시) |
| 출력 | 빈 퀴즈 안내 | 준비된 퀴즈가 없을 때 빈 안내 문구 한 줄 — strings.xml(parked_quiz_empty) |
| 출력 | 단계 전환 | 마지막 문항 답변 후 '그때와 지금' 단계로 자동 전환 — ParkedSteps.kt QuizStep(stepIndex = 2) |
| 상태 | 진행 보존 | QuizStateHolder — 문항 인덱스·고른 보기·채점 결과를 장소 단위로 보존(프로세스 수명 싱글톤) |
| 상태 | 단계 구조 | 정차 화면의 단계 전환은 ParkedSteps.kt의 QuizStep(stepIndex)이 담당 — 마지막 문항 답변 뒤 stepIndex = 2로 '그때와 지금' 진입(AC09) |
| 상태 | 초안 분류 | reviewed=false 6문항 — SeedRepositoryTest가 전 문항 초안을 단언 |

수용 기준은 EARS(요구를 다섯 모양의 한 문장으로 쓰는 방법)로 쓰여 있고, 아래 표는 정본 JSON에서 생성했습니다.

|---|---|---|---|---|

| AC02 | 사건 | 고른 보기가 오답이면 앱은 올바른 보기 문장을 '정답: …' 형태로 함께 보여줍니다. | 코드 확인 | (설계) |
| AC03 | 상태 | 차가 주행 중인 동안 앱은 퀴즈가 있는 정차 화면으로 전환하지 않습니다. | 단위 시험 | [코드 확인] |
| AC04 | 사건 | 차가 정차하고 가족 세션이 있으면 앱은 퀴즈 단계를 포함한 정차 화면으로 전환합니다. | 단위 시험 | [코드 확인] |

| AC08 | 금지 | 도착한 장소에 준비된 퀴즈가 없으면 앱은 빈 안내 문구 한 줄만 보여주고 화면을 멈추지 않습니다. | 코드 확인 | (설계) |

## 5. 입력→출력 예시

**장소 도착(AC06·AC07).** 국립경주박물관에 도착하면 그 장소에 묶인 퀴즈 2문항이 순서대로 노출됩니다. 문항은 APK 내장 시드에서 읽으며, 전 문항이 검수 전이라 문항 머리에 '1/2'와 '초안' 표시가 붙습니다. 이 화면은 실측 화면 8(2026-11-12 캡처)로 남아 있고, 시드 구성 자체는 SeedRepositoryTest realSeedFile_parsesToExpectedContent가 단언합니다.

**오답 선택(AC02).** 3개 보기 중 오답을 고르면 화면에 '정답: (실제 정답 보기 문장)' 한 줄이 함께 표시됩니다. 정답을 고르면 '정답이에요!'와 해설이 표시됩니다. 문장은 strings.xml 리소스이고 화면 분기는 ParkedSteps.kt의 QuizStep이 담당합니다.

**주행 전환 후 복귀(AC10).** 1번 문항을 풀던 중 주행으로 화면이 가려졌다가 다시 정차하면 1번 문항·고른 보기·채점 결과가 그대로 유지된 채 다시 표시됩니다. Activity 인스턴스가 파괴될 수 있어 상태를 프로세스 수명 싱글톤(QuizStateHolder)에 둡니다 — 소스 app/src/main/java/app/arosaegim/ui/parked/QuizState.kt.

**정답 선택(AC01).** 고른 보기가 정답이면 '정답이에요!' 한 줄과 해설이 표시됩니다. 오답(AC02)과 마찬가지로 문장은 strings.xml 리소스이고 화면 분기는 ParkedSteps.kt의 QuizStep이 담당합니다. 채점 문장의 화면 실측은 아직 남아 있습니다((설계) 상태).

**단계 전환(AC09).** 그 장소의 마지막 문항에 답하면 앱은 자동으로 '그때와 지금' 단계로 넘어갑니다. 화면 코드는 ParkedSteps.kt의 QuizStep이 단계(stepIndex)를 바꿔 처리하며, 이 전환의 화면 실측은 아직 남아 있습니다((설계) 상태).

**전환 보류(AC05).** 기어 P로 진입했지만 가족 세션이 없으면 정차 화면(퀴즈 포함)으로 전환하지 않고 시작 화면을 유지합니다 — 단위 테스트 ModeRouterResolveTest `정차 상태에서 세션이 없으면 전환을 보류한다(Q28 - 시작 화면 유지)`.

아래는 정본 JSON의 io 필드를 요약 없이 인용한 것입니다.

| AC | 입력 | 출력 |
|---|---|---|
| AC02 | 3개 보기 중 오답 선택 | '정답: (실제 정답 보기 문장)' 한 줄 표시 |

| AC10 | 1번 문항 풀이 중 주행 전환 → 재정차 | 1번 문항·고른 보기·채점 결과가 그대로 유지된 채 다시 표시 |

## 6. 오류·예외 처리

- 도착한 장소에 준비된 퀴즈가 없으면 빈 안내 문구 한 줄만 보여주고 화면을 멈추지 않습니다 — strings.xml(parked_quiz_empty), 소스 app/src/main/java/app/arosaegim/ui/parked/ParkedSteps.kt(QuizStep).
- 주행 중에는 라우팅 규칙이 정차 화면(퀴즈 포함)으로 전환하지 않고, 세션이 없으면 전환을 보류해 시작 화면을 유지합니다 — 단위 시험 ModeRouterResolveTest(주행 두 케이스·세션 없음 보류), 근거의 상세는 [F2 문서](F2_주행정차전환.md) 6절.
- 주행 시작으로 ParkedActivity 인스턴스가 파괴되는 상황에 대비해 퀴즈 진행 상태를 Activity에 두지 않고 QuizStateHolder 싱글톤에 둡니다. 장소가 바뀌었을 때만 초기화합니다 — docs/ARCHITECTURE.md 3절·9절 Q13.
- 시드 파싱 자체가 실패하는 경우(깨진 시드)는 빈 내용으로 복구해 크래시하지 않습니다. 이때 퀴즈 목록도 비게 되므로 위의 빈 퀴즈 안내가 그 상황의 화면 결과가 됩니다 — 단위 시험의 위치는 [F9 문서](F9_오프라인대체구현.md) 6절.
- 문항이 검수 전이라는 사실은 화면에서 숨기지 않습니다 — '초안' 꼬리표로 그대로 보여줍니다. 검수 전 6문항 전부가 이 상태이고, 표시까지 실측 화면 8(2026-11-12 캡처)로 남아 있습니다(AC07).

## 7. 시험·실측 연결

**단위 시험** (android/app/src/test)
- SeedRepositoryTest — 실제 시드 파일 파싱(장소별 퀴즈 2개·전체 6문항·전 문항 초안 단언).
- ModeRouterResolveTest — 주행 중 전환 금지 두 케이스·세션 있음 전환·세션 없음 보류([F2 문서](F2_주행정차전환.md)와 시험 대상 공유).

**에뮬레이터 실측** (실측 화면 캡처)
- 실측 화면 8(2026-11-12 캡처) — 퀴즈 문항 머리의 '1/2'와 '초안' 표시(AC07 [확인]의 근거).
- 정차 화면의 진입·복귀 동작은 F2 문서의 실측(스모크 U9 — 3회 전환·복귀, 개발 기록 F72 — D→P 자동 복귀 2회)으로만 커버됩니다.

**아직 실측 전**
- AC01·AC02 — 채점 문장(strings.xml과 화면 분기 근거만).
- AC08 — 빈 퀴즈 안내.
- AC09·AC10 — 단계 전환(stepIndex 전환)·진행 보존(QuizStateHolder).
- 퀴즈 채점·단계 전환의 화면 실측 기록은 개발 기록에 별도 항목이 없습니다.
