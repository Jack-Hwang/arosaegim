# F6 가족 코드·PIN·세션

## 1. 한눈에 보기

가족 코드(6~8자리 영숫자)·PIN(6자리·세션 메모리 전용)·세션 상태에 따른 화면 전환·로그아웃 삭제·인증 거부 안내를 다루는 기능입니다.
PIN은 어디에도 저장되지 않고(세션 메모리만), 가족 코드만 기기에 남겨 다시 켜도 접속이 이어집니다. 가족 없이 둘러보기(guestMode)를 고르면 기록이 이 차량에만 남습니다.
정차 자동 전환의 세션 게이트는 콜드 스타트 실측까지 끝났습니다(AC07 — [확인]). PIN 거절 안내(AC12)는 (설계)에서 [코드 확인]으로 갱신된 항목입니다 — 전송 경로의 PIN 거절 표시 구현과 단위 시험 3건이 이를 실현했습니다(이 문서 6절).
수용 기준 14건 중 [확인] 1·[코드 확인] 7·(설계) 6입니다.
아직 미확인인 것: 코드·PIN 입력 → 출발 → 도착 → 서버 기록의 전체 경로 실측(개발 기록 Q29), (설계) 6건의 화면 실측입니다.

## 2. 목적과 범위

| 요소 | 내용 |
|---|---|
| 포함 | FamilyCodeValidator(6~8자리 영숫자·공백·특수문자·한글 거부), 입력 필터(문자 남김·8자 제한 — 형식 검사는 접속 시), PIN 입력(숫자 6자리·가려진 입력란), SessionCredentials(메모리 전용 PIN·거절 표시), FamilySessionStore(코드만 저장·대문자 정규화·guestMode), 라우팅 세션 게이트(hasSession), 로그아웃(파일 2개 삭제·부분 실패 계속), ApiClient의 401·403 → AuthException 계약, PIN 거절 표시(거부된 PIN의 메모리 삭제·재전송 중단·안내 한 줄) |
| 제외 | 서버의 PIN 잠금·코드 재발급·물려주기(정본 기준은 [F7 문서](F7_가족기록서버모바일웹물려주기.md)), 전송 대기열의 FIFO·멱등키 세부([F9 문서](F9_오프라인대체구현.md)), 정차·주행 판정 자체(F2 문서 — 이 문서는 세션 유무에 따른 전환 분기만) |
| 가정 | PIN은 식별이 아니라 열람·수정용이라 차량 기기에 영속 저장하면 탈거·공유 차량에서 유출 위험이 있습니다(docs/ADR.md ADR-003). 앱 재시작 시 PIN은 소실되고 재입력을 요구합니다(개발 기록 F59). 서버가 발급하는 코드는 8자리이므로 검증은 6~8자리를 허용합니다(개발 기록 F58 — docs/ADR.md ADR-009) |
| 경계 | 코드는 기기에 남고 PIN은 남지 않습니다. 거절 표시 중에는 PIN 조회가 null이 되어 헤더·대기열·화면 조회가 재전송을 멈춥니다 — 소스 app/src/main/java/app/arosaegim/data/FamilySessionStore.kt(pinOrNull·markRejected 주석). 로그아웃 버튼은 지금 개발용 진단 화면에만 있고 릴리스 앱에서는 그 화면이 열리지 않습니다(정본 AC10 note — 설정 화면은 계획) |

## 3. 입력·출력·상태

| 구분 | 항목 | 내용 |
|---|---|---|
| 입력 | 가족 코드 문자열 | 입력칸은 문자·숫자를 8자까지만 받고, 6~8자리 영숫자 형식 검사는 접속 버튼 시점에 FamilyCodeValidator가 합니다(AC03) |
| 입력 | PIN 입력 | 시작 화면 한 곳에서 숫자 6자리·가려진 입력란 — StartScreen.kt(PIN_MAX_LENGTH=6) |
| 입력 | 기어 상태 | 정차 상태 수집 — 세션 유무에 따라 전환 실행·보류(AC07) |
| 입력 | 서버 응답 | 401·403은 AuthException(PIN 재입력 신호), 404·429 등은 일반 실패(ApiClient.kt) |
| 출력 | 판정·버튼 | 코드 유효 + PIN 6자리 충족 시 [이어 보기] 활성(AC04) |
| 출력 | 세션 저장 | 가족 코드만 SharedPreferences(family_session)에 저장·대문자 정규화(AC06·AC13), PIN 저장 경로 없음(AC05) |
| 출력 | 안내 줄 | PIN 거절 시 재입력 안내 한 줄(TripSession.kt PIN_REJECTED_LINE — "PIN이 맞지 않아요. 가족 코드 화면에서 다시 입력해 주세요"), 구성원 조회 거부 시 "가족 코드·PIN을 다시 확인해 주세요"(strings.xml parked_seat_names_auth_error) |
| 출력 | 삭제 결과 | 로그아웃 시 코드 삭제·PIN 해제·visits.json·visit_queue.json 삭제 — 파일별 결과 줄(SignOutCleanup) |
| 상태 | 세션·거절 | hasSession(코드 또는 둘러보기), isRejected(거절 표시 — setPin·clearPin·signOut에서 해제), guestMode |

## 5. 입력→출력 예시

**코드 입력(AC01·AC03·AC04).** 입력칸에 코드를 넣으면 공백·기호만 걸러지고 8자까지만 남습니다(한글 글자는 남습니다). 6자리 코드("A1B2C3")는 유효, 9자리("A1B2C3D4E")는 무효이고, 유효한 코드 + PIN 6자리가 갖춰지면 [이어 보기]가 활성화됩니다 — 단위 테스트 FamilySessionStoreTest(6·7·9자리 케이스 — 서버가 8자리 코드를 발급한다는 근거는 개발 기록 F58), StartScreen.kt(활성 조건식).

**PIN 수명(AC05).** PIN "230444"를 입력하면 세션 메모리에만 남고(기기 저장소·파일 기록 없음), 앱 프로세스를 다시 시작하면 PIN은 사라져 다시 입력이 필요합니다 — 단위 테스트 FamilySessionStoreTest("pin을 설정하면 pinOrNull로 같은 값이 나온다", "공백뿐인 pin은 없는 것과 같다"), 개발 기록 F59.

**세션 게이트(AC07).** 세션 없이 첫 정차 상태가 수집되면 화면 전환이 없고(시작 화면 유지), 둘러보기를 선택한 뒤의 정차 수집은 정차 화면으로 전환됩니다 — 콜드 스타트 실측(개발 기록 F80)과 모드 라우터 단위 테스트가 함께 근거입니다.

**거부 응답(AC12·AC14).** 구성원 조회가 401·403으로 거부되면 이름표 카드를 숨기지 않고 "가족 코드·PIN을 다시 확인해 주세요" 안내 한 줄을 보여줍니다. 전송 경로의 PIN 거절(2026-11-13 구현)도 안내가 갈린다 — 거부된 PIN은 세션 메모리에서 즉시 지워 재전송이 멈추고(아래 6절), 반면 서버의 429 잠금 응답은 별도 안내 없이 일반 실패로 처리됩니다(AC14).

## 6. 오류·예외 처리

- 401·403은 AuthException으로 구분돼 PIN 재입력 신호가 되고, 404(모르는 코드·장소)·429(PIN 오류 잠금) 등은 AuthException이 아니라 일반 실패로 흡수됩니다 — 소스 app/src/main/java/app/arosaegim/data/ApiClient.kt(주석·throw 경로). 이 때문에 AC14의 한계가 있습니다: 서버의 429 잠금 응답은 별도 안내 없이 일반 전송 실패로 처리됩니다.
- PIN 거절 표시(2026-11-13 구현 — AC12를 [코드 확인]으로 갱신한 근거): 서버가 PIN을 거부하면 VisitQueue가 거부된 (가족 코드, PIN) 조합을 메모리에 기록하고 전송을 멈춘 채 큐를 보존합니다. FamilySessionStore.markRejected가 PIN 값을 메모리에서 즉시 지워(pinOrNull이 null) 같은 틀린 PIN의 재전송으로 서버 잠금 횟수(5회)를 채우는 일을 막습니다. 값 비교만 하고 저장·로그는 하지 않습니다 — 소스 data/VisitQueue.kt(PinRejectedException·rejectedPair), data/FamilySessionStore.kt(markRejected·rejectSessionPin), 단위 테스트 FamilySessionStoreTest("거절 표시하면 pinOrNull은 null이 되고 코드는 유지된다"), VisitQueueTest("11_서버가 PIN을 거부하면 같은 조합 재전송을 멈추고 큐는 보존된다"), TripSessionTest("15_큐 flush의 PIN 거절은 재입력 안내 한 줄을 남긴다").
- 거절 상태는 사용자의 새 PIN 입력(setPin)·해제(clearPin)·로그아웃(signOut)에서 풀립니다. 거절 응답이 늦게 도착해 사용자의 새 PIN을 지우지 않도록, 거부된 값과 현재 세션 PIN이 같을 때만 거절로 처리합니다 — 소스 data/FamilySessionStore.kt(markRejected 주석), 단위 테스트 FamilySessionStoreTest("setPin으로 새 pin을 넣으면 거절이 풀린다").
- 로그아웃 중 파일 하나가 삭제되지 않으면 나머지 삭제를 멈추지 않고 결과를 한 줄씩 남깁니다 — 단위 테스트 로그아웃 정리 단위 테스트("한 파일 삭제 실패가 나머지 삭제를 막지 않는다")(AC11).
- 세션이 없는 앱의 방문은 전송이 401로 보류되고 대기열에 남습니다. 서버 DB 대조에서 방문이 0건으로 확인됐습니다(전송 보류가 설계대로 동작한 대조 기록) — 개발 기록 F78, docs/ADR.md ADR-003의 결과 문단.
