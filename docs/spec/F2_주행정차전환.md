# F2 주행/정차 전환

## 1. 한눈에 보기

주행 규제 신호(1차)와 기어 신호(보조)를 합쳐 주행·정차를 판정하고 화면을 바꾸는 기능입니다.
두 신호가 어긋나면 더 제한적인 쪽인 주행으로 판정하고, 기어 P가 5초(2초 폴링 3회) 지속되면 정차로 판정을 바꿉니다(개발 기록 F81).
주행 화면만 주행 최적화(DO)를 선언해 주행 중 사용을 허용받고, 정차 화면은 주행 시작 시 시스템이 가려 퀴즈·입력이 막힙니다.
수용 기준 14건 중 [확인] 1·[일부 확인] 4·[코드 확인] 7·(설계) 2입니다.
아직 미확인인 것: DO를 선언한 화면도 함께 가려진 사례의 원인(AC06 정본 note), 세션 게이트를 넣은 뒤 빌드의 자동 전환 재실측(AC08 note), 기어 P 5초 규칙의 에뮬레이터 재실측(AC14 note)입니다.

## 2. 목적과 범위

| 요소 | 내용 |
|---|---|
| 포함 | CarUxRestrictionsManager 등록(1차 신호), 기어 보조 신호의 2초 주기 폴링, 병합 규칙(어긋나면 더 제한적인 주행 우선·기어 P 5초 지속 시 PARKED 전환), 기어 신호를 못 읽었을 때의 1차 신호 단독 판정, DO 선언(DrivingActivity만), ModeStateMachine·ModeRouter의 화면 전환, 정차 자동 전환의 세션 게이트, 퀴즈 상태 보존(QuizStateHolder), 신호 등록 실패 시 수동 전환 표시(데모 모드) |
| 제외 | 퀴즈 화면의 문항·채점 내용(F3 문서), 가족 세션의 내용(F6 문서), 기어 값의 진단 화면 표시(스모크 U5 — 진단 기능), 도착 판정(F1 문서) |
| 가정 | 주행 최적화(DO)를 요구하는 순간이 화면을 최소화해야 하는 순간이라는 판단 — 앱의 관심사(퀴즈·긴 텍스트 금지)와 이 신호가 겹친다(docs/ARCHITECTURE.md 3절). 기어 P에서는 차가 움직일 수 없다는 물리 사실을 5초 해제 규칙의 근거로 쓴다(개발 기록 F81 — Q26 해소) |
| 경계 | 주행 중 퀴즈·입력 금지는 앱 코드가 아니라 플랫폼의 화면 가림으로 지켜집니다(AC05). 정차 화면 전환은 세션이 있을 때만 자동으로 하고, 주행 화면 전환은 세션과 무관하게 합니다(AC09·AC10). 세션 게이트를 넣기 전 빌드의 실측 결과(U9·F72)와 게이트 추가 뒤 빌드는 구분해서 기록합니다 |

## 5. 입력→출력 예시

**신호 어긋남(AC02).** 1차 신호가 정차를, 기어가 주행을 보고하면 주행으로 판정하고, 1차 신호가 주행을, 기어가 정차를 보고하면 주행을 유지합니다. 두 경우 모두 더 제한적인 주행 쪽이 이기며, 근거는 docs/ADR.md ADR-005와 DrivingStateMergerTest의 두 케이스입니다.

**기어 P 5초 전환(AC14).** 기어 P 신호가 5초 이상(2초 주기 폴링 3회) 연속 확인되는 동안 1차 신호가 주행을 유지해도 병합 결과가 정차(PARKED)로 전환됩니다. 근거는 개발 기록 F81(Q26 해소 — D→P 직후 주행 규제 신호가 주행을 유지한 잔존 사례 1회)과 DrivingStateMergerTest의 보류 시간 케이스입니다. 에뮬레이터 재실측은 아직입니다(정본 note).

**화면 가림(AC05·AC06).** 정차 화면이 떠 있는 동안 주행을 시작하면 시스템이 정차 화면을 가리고 "주행 중에는 사용할 수 없습니다" 문구를 보여 줍니다(개발 기록 F68 — 실측 [확인]). 같은 실측에서 DO를 선언한 주행 화면도 함께 가려진 사례가 있었고, 그 원인은 아직 확정하지 못했습니다(AC06 — 정본 note).

**세션 게이트(AC08·AC09).** 가족 코드로 접속한 상태에서 기어 D→P로 전환하면 정차 화면으로 자동 전환합니다(2회 실측 — 개발 기록 F72, 단 세션 게이트 넣기 전 빌드). 세션 없이 첫 정차 상태가 수집되면 전환을 보류해 시작 화면을 유지합니다(개발 기록 F80 — 콜드 스타트 실측). 정본 note에 따르면 그 순간 보인 화면은 디버그 빌드의 진단 화면이었고(F79) 가족 코드 입력 화면이 실제로 보이는지는 별도 확인이 필요합니다.

## 6. 오류·예외 처리

- 주행 규제 신호 등록이 실패하면(Car 서비스 부재 등) 상태를 PARKED로 유지하고 ManualDrivingState(데모 모드)로 폴백합니다. 폴백에서 파생 상태를 만들지 않는 것이 원칙입니다 — docs/ARCHITECTURE.md 3절, docs/ADR.md ADR-005, 소스 app/src/main/java/app/arosaegim/fallback/ManualDrivingState.kt. 화면 실측은 남아 있습니다(AC13 — 정본 note).
- D→P 전환 직후 주행 규제 신호(DO)가 주행을 유지한 잔존 사례가 실측됐습니다(Q26 — 실증). 코드 대응으로 기어 P 5초 지속 시 정차 전환 규칙을 추가했습니다(개발 기록 F81) — 단, AC14 note가 에뮬레이터 재실측 대기로 기록합니다.
- 화면 전환 startActivity가 실패하면 진단 화면의 '마지막 오류'에 기록합니다. NEW_TASK 플래그가 없어 전환이 조용히 실패했던 과거(E2E 감사 E3)가 있어 플래그를 고정했습니다 — docs/ADR.md ADR-006, 단위 시험 ModeRouterResolveTest.
- 기어 신호를 읽지 못한 결과(null)는 판정에 영향을 주지 않습니다 — 단위 테스트 DrivingStateMergerTest `보조를 못 읽었으면 판정에 영향을 주지 않는다`(AC03).
- CarUxRestrictionsManager의 해제는 무인자 시그니처만 존재합니다(SDK AAR 확인 — 개발 기록 F16).

## 7. 시험·실측 연결

**단위 시험** (android/app/src/test)
- DrivingStateMergerTest — 병합 규칙(더 제한적 우선)·기어 P 보류 해제(Q26)·못 읽은 기어 무시.
- CombinedDrivingStateTest — 못 읽은 기어 결과가 판정을 흔들지 않음.
