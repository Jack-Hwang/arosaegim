## 2. 프로젝트 헌장

> **한눈에 보기**
> 목표는 본문 2번을 그대로 가리킵니다(다시 쓰지 않습니다). 범위는 Must·Should·하지 않는 것(Won't)으로 나누고, 하지 않는 것 여섯 가지에는 각각 근거(설계·제품 결정 번호 또는 코드 확인)를 달았습니다.
> 성공 지표는 시험 통과 수 같은 품질 지표를 중심으로 쓰고, 사업성 지표는 본문 6번을 가리킵니다. 상위 위험 5가지와 일정은 본문 5번의 내용을 추립니다 — 새 날짜는 만들지 않습니다.


### 목표

목표는 세대를 이은 가족 여행의 발자취를 다음 세대에게 그대로 물려주고, 그 여행이 지역 식당·가게 소비로 이어지게 하는 것입니다(본문 2번 '목표'). 기획 배경의 아버지 이야기는 본문 2번을 그대로 가리키며 이 별지에서 다시 쓰지 않습니다.


### 범위 — Must·Should·하지 않는 것(Won't)

범위를 정할 때는 먼저 이 기능이 목표(가족 기록을 잇는 것)에 꼭 필요한지 묻고, 그다음 차량 환경에서 주행 중 입력을 요구하지 않고 다룰 수 있는지 묻고, 마지막으로 다른 기능과 함께 두었을 때 문제가 없는지 봅니다.

Must는 이 세 물음을 모두 통과해 1차 제출에 넣은 범위이고, Should는 앞의 두 물음은 통과했지만 화면 실측 같은 마지막 확인이 2차 발표로 남은 범위입니다.

아래 표의 '근거' 칸은 두 가지 번호를 씁니다. 하나는 저장소의 설계 결정 기록(영어 약자로 ADR)이 매긴 번호이고, 다른 하나는 이 기획서가 새로 매기는 제품 결정 번호(PD)입니다.

**범위(Must·Should·하지 않는 것)**

| 구분 | 내용 | 근거 |
|---|---|---|
| Must | 코스→도착 스탬프→퀴즈→'그때와 지금' 핵심 흐름 구동(F1·F3·F4), 주행/정차 전환과 주행 중 입력 제한(F2), 위치 비저장 등 개인정보 원칙 | 본문 5번 '단계별 범위'(1차) |
| Should | 가족 코드·PIN·서버 동기화(F6·F7), 포인트 캐시백 시뮬레이션(F8), 음성 해설·편지(F5), 물려주기·가족 누적 거리·사진 속 이름(F7), 내비게이션 경로 확인 | 본문 5번 '단계별 범위'(2차) |
| Won't | 차량 화면에서 글자·사진·금액을 입력하는 것(가족 코드·PIN 입력 화면은 제외) | 제품 결정 PD-05(차량 입력 없음), 가족 코드는 ADR-009·PIN은 ADR-003 |
| Won't | 차가 지나온 이동 경로(좌표 궤적)를 저장하는 것 | 제품 결정 PD-03 |
| Won't | 차대번호(VIN)를 읽거나 저장하는 것 | [코드 확인] capability만 확인하고 값 자체는 호출하지 않음(PleosVehicleInfoProvider.checkVinCapabilityOnly) |
| Won't | 포인트를 계좌 이체 등 현금성 수단으로 바꿔 주는 것 | 제품 결정 PD-05(사용처는 제휴 후 정함, 서버 코드에 전환 경로를 두지 않음 — 코드 확인) |
| Won't | 고인의 목소리 등을 AI로 새로 만들어 내는 것 | 제품 결정 PD-01(생성형 AI를 호출하지 않는다는 원칙의 적용 사례) |
| Won't | 앱 안에서 생성형 AI(문장·음성을 새로 만들어 내는 모델)를 호출하는 것 | 제품 결정 PD-01(Pleos의 생성형 AI 연동 도구는 제공이 끝남 — 개발 기록 F24) |

*제품 결정 PD 번호는 저장소 설계 결정 기록(ADR)과 번호를 섞지 않는 제품·정책 결정이며, 자세한 맥락과 기각한 대안은 별지 '명세와 설계 결정'의 설계 결정 기록(제품 결정) 절에 있습니다.*

위 '하지 않는 것'은 기능을 줄인 결과가 아닙니다. 가장 단순한 구조로 핵심 가치(가족 기록을 잇는 것)에 먼저 집중하고, 필요하다고 확인된 곳에만 기능을 더하기로 한 설계 선택입니다. 사용자가 못 박은 기능(스탬프·퀴즈·로컬 맛집·숙소 포인트 캐시백)과 분량은 이 범위 정리로 줄거나 바뀌지 않습니다.


### 성공 지표

- **품질**: 최신 측정(2026-11-14) 기준 앱 단위 시험 197/197·서버 시험 87/87 통과. 수용 기준(AC)의 다섯 유형 포함 여부와 상태 분포는 별지 '명세와 설계 결정'의 추적표에서 집계합니다.
- **실측**: 에뮬레이터 실측 결과표(U1~U16) 가운데 [확인]으로 표시된 항목의 비율. 아직 [미확인]·[일부 확인]인 항목은 숨기지 않고 그대로 둡니다.
- **문서 정확성**: 저장소의 숫자 자동 대조 도구가 사실 대장과 대조해 일치한 항목 수(개발 기록 F85 기준 9건 일치).
- **사업성**: 재이용률 등 사업성 지표와 목표 값은 본문 6번과 별지 '사업·운영 보강 자료'의 지표 표를 그대로 따르며 이 별지에서 다시 쓰지 않습니다.


### 상위 위험 5가지

**상위 위험 5가지(본문 5번 '위험과 대응'에서 추림)**

| 위험 | 지금 상태 |
|---|---|
| 기어 D 상태에서 시스템이 앱 화면을 가려 주행 화면이 보이지 않을 수 있음 | 주행 최적화 인정 조건 사무국 확인 전 |
| 주행 화면이 허용되는 앱 분류가 아직 정해지지 않음 | 사무국 문의 예정 |
| 음성 합성(차량·안드로이드 모두)이 끝내 되지 않을 수 있음 | [실패], 원인 2건 확인(세부는 미확인) |
| 세션이 있어도 정차 화면 자동 전환이 늦거나 안 될 수 있음 | 게이트 적용 후 재실측 전 |
| 이미 구현한 기능(물려주기·가족 누적 거리 등)의 화면 실측이 일정에 못 미칠 수 있음 | 코드 구현, 화면 실측 전 |

*다섯 가지 모두 새로 찾은 위험이 아니라 본문 5번에 이미 적힌 목록에서 상위 항목을 추린 것이며, 대응 방법도 본문 5번과 같습니다.*
