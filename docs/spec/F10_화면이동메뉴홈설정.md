# F10 화면 이동·메뉴·홈·설정

## 1. 한눈에 보기

F10은 구현됐습니다 — 에뮬레이터 화면 실측(캡처) 전이며, 시스템 프로필·세로(1:1) 창 실측 같은 T5·T6 항목과 둘러보기 문구 가름(AC16)은 (계획)으로 남습니다. 이 기능은 화면 위쪽의 머리말(Page Navigation)·[☰ 메뉴] 패널·홈 화면·설정 화면의 로그아웃과 가족 전환 경로, 화면 가림·주행 중 제한 같은 화면 규칙을 다루는 수용 기준 23건을 정리합니다.
지금 앱의 화면 이동은 F2(주행·정차 전환)가 담당하고, 정본에서 코드로 확인된 20건([코드 확인])은 구현·단위 시험까지 끝난 동작입니다 — 머리말·세그먼트 2건, 세션 없는 정차 보류 1건, 가족 코드 하나만 저장 1건과 이번에 구현된 메뉴·홈·설정·가족 전환 16건.
나머지 3건((계획))은 둘러보기 문구 가름(AC16)·세로 창 실측(AC17)·시스템 프로필 실측(AC22)입니다 — 이 문서는 구현된 것과 계획인 것을 상태 표기로 구분하고, 계획 항목을 구현된 것처럼 쓰지 않습니다.
[코드 확인] 20건은 [확인]이 아니라 코드·단위 시험까지의 상태입니다 — 전 항목이 에뮬레이터 화면 실측 전이고, 설정·가족 전환 화면 계열(AC04·AC12~AC15)은 화면 컴포넌트와 정리 흐름(SignOutFlow)까지 구현·단위 시험됐으나 메뉴 항목→설정 화면 라우트 렌더링(통합 배선)이 남아 있습니다.

## 2. 목적과 범위

| 요소 | 내용 |
|---|---|
| 포함 | 시작·정차 화면 위쪽의 머리말(Page Navigation — 앱 아이콘·앱 이름·코스 부제), 정차 화면의 5단계 세그먼트 머리말, 세션 없을 때의 정차 전환 보류, [☰ 메뉴] 버튼과 패널(홈·코스 선택·그때와 지금·설정), 홈 첫 화면(이어서 하기 카드·지난 방문 카드·첫 기록 안내), 설정 화면(가족 코드 마스킹·가족 전환·이 차에서 로그아웃·표시 스위치·개인정보 안내), 가족 전환 확인 화면, 가족 코드 화면 가림(앞 2자리·뒤 2자리), 주행 중 화면 제한(설정·가족 전환을 열지 않음) |
| 제외 | 주행·정차 화면 전환 판정 자체([F2 문서](F2_주행정차전환.md)), 세션·PIN의 저장과 거절 규칙([F6 문서](F6_가족코드PIN세션.md) — AC03·AC19는 F6의 동작을 화면 관점에서 본 것), 도착 스탬프 카드의 내용(F1 문서), 서버의 PIN 잠금 판정 자체(backend config.py·security.py — 이미 구현된 동작이며 이 기능은 화면 안내만 더한다), 표시 스위치의 저장·조회 API 계약(PartyPrefs — F7 문서) |
| 가정 | 메뉴 패널은 주행 중 최소 정보 원칙에 따라 주행 전환 때 닫힙니다(AC07 — 구현·단위 시험됨). 시작 화면의 코드 입력칸은 입력 중이라 가리지 않는 기존 설계를 유지합니다(AC18 note — 화면 가림이 노출 방지 장치). 새 화면에서도 차량 시스템 프로필을 읽거나 저장하지 않습니다(AC22 — 소스에도 경로 없음, 실측은 계획) |
| 경계 | 설정 화면 컴포넌트와 [이 차에서 로그아웃] 버튼·정리 흐름(SignOutFlow)은 구현·단위 시험됐으나 메뉴 항목→설정 화면 라우트 렌더링과 SignOutFlow 연결(통합 배선)이 남아 있어 아직 화면 경로가 열리지 않았습니다(AC04·AC15 note). 가족 전환 확인 화면은 SignOutFlow를 직접 부르지 않고 onConfirm 콜백으로만 답합니다(AC14 note — 실행·시작 화면 열기는 통합 몫). 설정·가족 전환 화면의 둘러보기 문구 가름(AC16)과 세로 창 실측(AC17)은 (계획)입니다 |

## 3. 입력·출력·상태

| 구분 | 항목 | 내용 |
|---|---|---|
| 입력 | [☰ 메뉴] 버튼 | 정차 중 누르면 오른쪽 패널을 엽니다(닫힌 채로 시작, 폭은 창 폭의 27%·최소 240dp) — AC06 [코드 확인]. 세션 없음·시작 화면에서는 버튼 자체가 없고 열림 요청도 무시됩니다(시작 화면이 곧 가족 코드·PIN 입력 화면) — AC05 [코드 확인] |
| 입력 | 주행·정차 전환 신호 | 패널이 열려 있는 채 주행으로 바뀌면 패널·메뉴 버튼·홈을 함께 감춥니다 — AC07 [코드 확인]. 세션 없는 정차 신호는 전환을 보류하고 시작 화면을 유지합니다 — AC03 [코드 확인] |

| 출력 | 머리말·세그먼트 | 시작·정차 화면 위쪽의 머리말(앱 아이콘·앱 이름·코스 부제)·정차 화면의 5단계 세그먼트, 머리글 trailingAction 자리의 [☰ 메뉴] 버튼 — AC01·AC02 [코드 확인] |
| 출력 | 패널·홈 | 네 항목 패널과 한글 항목 이름 통일(AC06·AC08), 홈 첫 화면·이어서 하기 카드·지난 방문 카드·첫 기록 안내(AC09·AC10·AC11), 도착 장면은 스탬프 획득 카드가 먼저(AC20) — 모두 [코드 확인] |

(계획) 3건의 내용은 다음과 같습니다 — AC16은 둘러보기일 때의 문구 가름(확인 화면은 지금 항목 5개를 모든 모드에 보여 줍니다), AC17은 세로(1:1) 창의 화면 캡처·가독성 실측(T5·T6 — 겹침 판정·화면 분기 자체는 구현·단위 시험됨), AC22는 시스템 프로필 실측(T5 — 새 화면 소스에도 읽기·저장 경로는 없습니다).
AC12·AC13·AC15처럼 일부 근거가 기존 동작인 항목의 설명 — 가족 전환 정리(SignOutFlow·SignOutCleanup)와 서버의 PIN 잠금 상수(config.py PIN_LOCK_ATTEMPTS=5·PIN_LOCK_MINUTES=10, security.py)는 코드로 확인했고, 화면 경로·안내의 에뮬레이터 실측은 남아 있습니다.
AC04·AC12·AC13·AC14·AC15(설정·가족 전환 계열)는 화면 컴포넌트·정리 흐름까지 구현·단위 시험됐으나 메뉴 항목→설정 화면 라우트 렌더링과 SignOutFlow 연결(통합 배선)이 남아 있고, 화면 실측도 전입니다.

정본: [docs/spec/ac/f10_navigation.json](ac/f10_navigation.json)

표의 '확인 방법'은 정본의 verify.kind를 한국어로 옮긴 것입니다 — 단위 시험(앱 JVM 테스트), 서버 시험(backend pytest), 에뮬레이터 실측(Pleos Connect 에뮬레이터 실행 기록), 코드 확인(소스 코드 근거), 없음(아직 정해지지 않음).
상태 어휘는 정본과 같습니다 — [확인]·[일부 확인]·[코드 확인]·[실패]는 시험·실측까지 끝난 정도를, (계획)은 구현·실측이 남은 항목을 뜻합니다.

## 5. 입력→출력 예시

**머리말·세그먼트(AC01·AC02 — [코드 확인]).** 정차 화면과 시작 화면 위쪽에 앱 아이콘·앱 이름·코스 부제 머리말이 있고, 정차 화면에는 스탬프·퀴즈·그때와 지금·스탬프북·오늘의 기록 5단계가 한 줄로 보입니다 — 소스 Components.kt PageNavigationBar(116~190행), ParkedComponents.kt ParkedPageNavigationBar. 머리말 오른쪽의 부가 기능 자리(trailingAction)에는 이제 [☰ 메뉴] 버튼(MenuButton, 229행)이 놓입니다(AC06 구현).

**세션 없는 정차 보류(AC03 — [코드 확인]).** 세션 없이 정차 상태가 수집되면 화면 전환이 없고 시작 화면(가족 코드 입력)이 유지됩니다(io: "세션 없음 + 정차 상태 수집" → "화면 전환 없음(시작 화면 유지)") — 단위 테스트 ModeRouterResolveTest "정차 상태에서 세션이 없으면 전환을 보류한다(Q28 - 시작 화면 유지)". 둘러보기 선택 뒤의 정차 전환은 [F6 문서](F6_가족코드PIN세션.md) AC07([확인])이 다룹니다.

**메뉴 패널(AC05·AC06·AC07·AC08 — [코드 확인]·AC17 — (계획)).** 정차 중 [☰ 메뉴]를 누르면(MenuPanelState.open) 화면 오른쪽에 홈·코스 선택·그때와 지금·설정 네 항목 패널이 열립니다(io: "정차 중 [☰ 메뉴] 버튼 누름" → "오른쪽 패널 열림(네 항목 표시)") — 패널은 닫힌 채로 시작하고 폭은 창 폭의 27%(최소 240dp, MenuPolicy.panelWidthDp)입니다. 가로 창에서는 본문 폭이 패널만큼 줄어들고(⒝ BODY_SHRINK), 세로·1:1 창에서는 본문 위에 겹치고 왼쪽이 어둡습니다(⒞ OVERLAY — 본문 폭 그대로). 세션 없음·시작 화면·주행 중에는 버튼이 없고 열림 요청도 무시됩니다(⒟·⒜ — 패널 강제 닫힘) — 규칙 판정은 MenuPolicy 순수 함수로 MenuPolicyTest 11건이 검증합니다. 세로 창의 화면 캡처·가독성 실측(AC17)은 아직 전입니다(T5·T6 — (계획)).

**홈 첫 화면(AC09·AC10·AC11·AC20·AC23 — [코드 확인]).** 세션이 있고 정차 중이며 도착 직후가 아니면 홈이 첫 화면입니다(HomeGate 순수 판정 — 화면이 앞으로 올 때마다 자동 판정으로 돌아가고 사용자의 홈·본문 선택이 있으면 그것이 이깁니다). 진행 중 코스가 있으면(스탬프·다음 목표가 하나라도 있음) 스탬프 진행과 다음 장소를 담은 "이어서 하기" 카드를 보여 주고(io: "진행 중 코스 있음" → 이어서 하기 카드), 마지막 방문 기록이 있으면 지난 방문 카드가 붙습니다. 카드가 하나도 없으면 "오늘이 우리 가족의 첫 기록입니다" 한 줄로 시작합니다(AC11 — 문구는 strings.xml home_first_title과 같습니다). 도착으로 정차 화면이 올라올 때는 홈이 아니라 스탬프 획득 카드(스텝 1)가 먼저입니다(AC20 — HomeGateState가 도착 직후를 기록하고 HomeGate가 홈을 닫습니다; 콜드 시작의 저장된 도착은 보호하지 않습니다). 서버에 닿지 않으면 거리 줄만 숨기고 오류 문구를 만들지 않습니다(AC23 — io: "서버 응답 없음 + 진행 중 코스 있음" → "로컬 값으로 이어서 하기 카드 표시, 오류 문구 없음").

**가족 전환·잠김 안내(AC12·AC13·AC14 — [코드 확인]·AC16 — (계획)).** [가족 전환]을 누르면(io: "[가족 전환] 누름" → "확인 화면 표시(삭제 전, 로그아웃 미실행)") 지워져요 5항목(가족 코드·PIN·이 차에 남은 방문 기록·전송 대기 기록·진행 중이던 코스와 퀴즈)과 그대로 남아요 3항목(서버의 가족 기록·스마트폰에서 올린 사진·포인트)을 먼저 보여 주고, [로그아웃하고 바꾸기]를 선택해야만 정리가 실행됩니다. 정리는 SignOutFlow.run() 한 번으로 ①가족 세션(코드·PIN)→②파일 2개(visits.json·visit_queue.json)→③이어받기 안내 메모리→④여행 세션(스탬프·진행·거리·인원)→⑤퀴즈→⑥코스 시작 상태→⑦큐 메모리 순서로 진행됩니다(io: "가족 전환 확인 화면에서 [로그아웃하고 바꾸기] 선택" → "삭제 + 시작 화면") — 확인 화면은 onConfirm 콜백으로만 답하고 SignOutFlow 실행·시작 화면 열기는 통합 배선 몫입니다. 둘러보기일 때의 문구 가름(AC16)은 아직 구현 전입니다 — 확인 화면은 같은 5항목 목록을 보여 주고 정리 동작 자체는 둘러보기도 같은 흐름입니다(SignOutFlowTest 3번). PIN 5회 연속 오류에는(io: "같은 가족 코드로 PIN 5회 연속 오류" → "서버 429(가족 잠김) + 화면에 10분 잠김 안내") 서버의 5회·10분 잠금(기존 동작)과 가족 전환 확인 화면의 상시 안내 문구(family_switch_note_lock)가 있고, 설정 화면 쪽 문구·배선·실측은 남아 있습니다.

**코드 가림·주행 제한(AC18·AC21 — [코드 확인]·AC22 — (계획)).** 화면에 보이는 가족 코드는 앞 2자리와 뒤 2자리만 남기고 가운데 자리를 불릿으로 가립니다(io: "가족 코드 A37K9Q2M" → "A3••••2M" — FamilyCodeMask.mask·MenuPolicy.maskFamilyCode, 4자리 이하는 전부 가림; 메뉴 패널·설정 화면은 마스킹 값만 그립니다). 시작 화면의 입력칸은 입력 중이라 가리지 않습니다(AC18 note — 화면 가림이 노출 방지 장치). 주행 중에는 메뉴 버튼이 없어 설정·가족 전환 화면으로 닿을 진입 경로가 없고(AC21), 차량 시스템 프로필은 읽거나 저장하지 않습니다(AC22 — 새 화면 소스에도 경로 없음, 실측은 (계획)).

## 6. 오류·예외 처리

- 세션 없는 메뉴 접근 — AC05 [코드 확인]: 세션 없음·시작 화면에서는 메뉴 버튼이 없고 열림 요청도 무시해 패널이 강제로 닫힙니다(MenuPolicy 규칙 ⒟). 시작 화면 자체가 가족 코드·PIN 입력 화면이라 별도 안내 화면은 없습니다. 세션 게이트의 정차 전환 쪽은 [F6 문서](F6_가족코드PIN세션.md) AC07([확인])입니다.
- 서버 없는 홈 — AC23 [코드 확인]: 거리 값이 없으면 그 줄만 숨기고 오류 문구를 만드는 경로가 홈에는 없습니다 — 기존 화면의 오류 한 줄 + 계속 진행 규칙과 같은 방향입니다(AC23 note).
- PIN 잠김(429) — AC13 [코드 확인]: 서버는 5회·10분 잠금으로 응답하고(backend config.py 상수·security.py 판정), 가족 전환 확인 화면에 상시 안내 문구(family_switch_note_lock — "PIN을 5번 틀리면 그 가족은 10분 동안 잠겨요")를 두었습니다. 429 거절은 F6의 거절 경로를 공유합니다 — 서버의 인증 거부(401·403·429)는 전송 큐에서 AuthException으로 실패 1회를 기록하고 세션 PIN 거절 표시를 남겨 재전송을 멈추지만([F6 문서](F6_가족코드PIN세션.md) 6절), 화면에는 잠김 전용 안내를 띄우지 않습니다(F6 AC14). 가족 전환·로그아웃의 SignOutFlow 정리가 이 거절 상태도 함께 지웁니다(① 가족 세션 해제·⑦ 큐 메모리 정리 — 대기 항목·거절 기록·PIN 보관). 설정 화면 쪽 문구·라우트 배선·실측은 남아 있습니다.
- 로그아웃 정리의 부분 실패 — AC12 [코드 확인]: SignOutFlow는 한 단계가 실패해도 나머지 단계를 계속 진행하고 결과 줄에 "…: 실패"로 남깁니다(파일 하나가 지워지지 않아도 큐 파일·메모리 상태·세션·퀴즈·코스 상태 정리는 계속됩니다). run()은 멱등이라 이미 정리된 상태에서 다시 불려도 예외 없이 "없음/초기화됨" 줄로 답합니다 — SignOutFlowTest 2·4번.
- 주행 중 화면 제한 — AC21 [코드 확인]: 주행 중에는 메뉴 버튼이 없어 설정·가족 전환 화면으로 닿을 진입 경로가 없습니다(MenuPolicy 규칙 ⒜ — 단위 시험). 정차 화면은 주행 최적화를 선언하지 않아 주행 중에는 시스템이 가리는 것이 기존 동작입니다.
- 도착 장면 보호 — AC20 [코드 확인]: 홈이 도착 장면을 가로채지 않게 하는 규칙으로, 도착 직후에는 홈을 닫아 스탬프 획득 카드가 먼저 보입니다(HomeGateState — 화면 진입·가림을 관찰해 기록; 콜드 시작의 저장된 도착은 도착 이벤트가 아니므로 보호하지 않습니다).
- 둘러보기 문구 가름 — AC16 (계획): 확인 화면은 둘러보기 여부와 무관하게 같은 5항목 목록을 보여 줍니다. 정리 동작 자체는 둘러보기도 같은 흐름입니다(SignOutFlowTest 3번), 문구 가름은 구현 전입니다.
