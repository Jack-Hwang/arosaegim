# 아로새김 — 가족 모바일 웹 (`web/`)

같은 문화유산을 세대가 다시 찾을 때, '그때'의 기록과 '지금'의 순간을 나란히 이어 주는 가족 스탬프 여행의 **가족용 모바일 웹**(보조 클라이언트). 영수증 포인트 적립 입력은 이 웹에서만 한다(02문서 6-3절).

- 정적 HTML + 바닐라 JS. **빌드 단계 없음** (02문서 1절).
- 스마트폰 세로 화면 기준, 글자 크게, 한국어 UI.
- 실명·이메일·전화번호 입력란은 어디에도 없다.
- 가족 코드·PIN은 **이 기기의 localStorage에만** 저장한다.

## 파일 구조

```
web/
  index.html            # 뼈대 + 스크립트 로드
  style.css             # 스타일 (토큰 기반, 인주색 포인트 하나)
  js/
    api.js              # fetch 계층: X-Family-Code / X-Family-Pin / X-Device-Token 헤더, 오류 → 한국어 한 줄
    app.js              # 공용 유틸(h/banner/modal/confirmDanger), 해시 라우터, 동의 게이트, 제휴처 이름 캐시
    screens/
      setup.js          # 홈: 가족 코드 발급(하루 1회·기기 토큰)·입력, 서버 주소 설정
      consent.js        # 개인정보 동의(동의/거부 명확 구분)
      courses.js        # 코스·장소 목록 + 스탬프 표시 + 스탬프북 진행(예시)
      record.js         # 그때 기록하기(party_size 포함, 사진 동의 체크 필수, B5 사진 속 사람 이름 표시)
      timeline.js       # 타임라인 + '그때와 지금' 상세(markers 이름 나열, 그때 연도·방문 순번·함께 달린 거리·가족 누적 거리 표시)
      family.js         # 구성원·계승 + T9-3 오늘의 자리(seat_role) + B4 인원 비교 문장 접기 되돌리기
      data.js           # 내려받기(ZIP), 코드 재발급, 맛집 기록, 가족 데이터 삭제
      receipt.js        # 영수증 인증(예시): 사진 필수·숙소 숙박 기간·pending + 캐시백 내역(제휴처 이름 표시)
  README.md
```

각 파일은 ~300줄 이하를 지향한다. 초과 시 이렇게 기능별로 분리했다.

## 서버 실행법 (backend/README.md 참조)

백엔드는 별도 담당이며 `glm/02_BACKEND_AND_DATA.md` 계약대로 만든다(Python 3.12 + FastAPI + SQLite). 백엔드가 `/web`을 정적으로 같이 서비스하는 구성(02문서 8절)을 전제한다.

```bash
# 백엔드 폴더에서 (정확한 명령은 backend/README.md 참조)
uvicorn app.main:app --reload --port 8000
```

## localhost 테스트 방법

1. **백엔드와 함께(권장)**: 백엔드를 8000 포트로 띄운 뒤 브라우저에서 `http://localhost:8000/web/` 접속. 이때 서버 주소 설정은 "기본(같은 오리진)" 그대로 둔다.
2. **UI만 확인(백엔드 없이)**: 저장소 루트에서
   ```bash
   python -m http.server 8080
   # 브라우저에서 http://localhost:8080/web/ 접속
   ```
   API 호출은 모두 실패하고 상단에 오류 배너가 뜬다(정상 동작 — 오류 처리 확인용).
3. **안드로이드 에뮬레이터 웹뷰**: 에뮬레이터에서 호스트는 `http://10.0.2.2:8000` 이다(02문서 1절). 홈 화면 "서버 주소"에 `http://10.0.2.2:8000` 을 입력하고 "연결 확인"으로 검사한다.

## API 계약 가정 (백엔드와 맞춰야 할 것들)

02문서 3·3-1·6절 계약을 따르되, 문서에 정해지지 않은 부분은 아래와 같이 구현했다. 백엔드 구현 시 맞춰 주거나 README를 고쳐야 한다.

1. **PIN 전달 규칙**: 가족 코드가 저장돼 있으면 모든 요청에 `X-Family-Code`를, `POST /v1/families`(발급)를 제외한 모든 요청에 `X-Family-Pin`을 함께 보낸다. PIN이 필요 없는 엔드포인트(공개 코스·장소 목록 등)는 서버가 헤더를 무시하면 된다.
2. **가족 코드 형식**: 실서버가 8자리 코드를 발급한다(`ABCDEFGHJKMNPQRSTUVWXYZ23456789`, 예: `K7M2QX4B`). 입력 검증은 **6~8자리 영숫자**(`/^[A-Z0-9]{6,8}$/`)로 완화했다(기존 가정 "6자리" 수정).
3. **발급 응답**: `POST /v1/families` → `{ family_code, pin }`(02문서 9절). PIN이 없으면 PIN 없이 저장.
4. **코드 재발급**: `POST /v1/families/me/rotate-code` → `{ family_code, pin }` 가정. `pin`이 없으면 기존 PIN을 유지한다.
5. **타임라인 ↔ 맛집 연결**: `POST /v1/families/me/food-notes`가 `visit_id`를 요구하므로, 타임라인 항목에 `visit_id` 필드가 있어야 한다(없으면 맛집 방문 선택 목록이 비어 보인다). `kind`는 `visit | memory` 외에 맛집은 `food` 또는 `food_note`로 올 수 있다고 보고 라벨을 맞춰 둠.
6. **포인트 응답 형태**: 실서버는 `GET /v1/families/me/points` → `{ total, entries: [...] }` 다. `entries`를 우선 읽고 과거 가정 키(`ledger`/`history`/`items`)와 배열 응답도 방어적으로 표시한다.
7. **스탬프북 응답**: `GET /v1/families/me/stamp-books`의 진행률 필드명은 문서에 없어 `stamped_count/total_count`(또는 `stamped/total`)를 방어적으로 읽는다.
8. **결제 시각 포맷**: `paid_at`은 `YYYY-MM-DDTHH:MM:00+09:00`(한국 시간대 명시)로 보낸다. 일일 한도 판정을 UTC로 하면 날짜가 어긋날 수 있다.
9. **사진 업로드**: 클라이언트에서 JPEG/PNG·5MB 이하만 통과시키고(서버 검증과 이중), multipart 필드명은 `photo`로 통일한다. EXIF 제거·파일명 재생성은 서버 몫(02문서 3절).
10. **내려받기**: `GET /v1/families/me/export`는 ZIP 바이너리를 돌려줘야 하며, 다른 오리진 테스트 시 CORS에 `Content-Disposition` 노출이 필요할 수 있다. 같은 오리진(/web 서비스)에서는 문제없다.
11. **then-now 사진**: `past.photo_url`이 상대 경로(`/uploads/...`)면 서버 주소를 앞에 붙여 표시한다.
12. **T9-3 자리 역할 저장(2026-11-10)**: 구성원 `seat_role`(02문서 10절 — `driver | navigator | explorer`)의 **변경**은 `PATCH /v1/families/me/members/{id}`에 `{ "seat_role": ... }`을 먼저 보내고, PATCH가 없으면(404·405·501) `POST /v1/families/me/members/{id}/seat-role`로 폴백한다. 두 엔드포인트 모두 서버에 아직 없으면 오류 배너 한 줄로 흐름이 깨지지 않는다. 구성원 **추가** 화면에서도 자리를 고를 수 있게 보내며, 서버가 아직 `seat_role`을 받지 않아 추가가 400/422로 거부되면 **seat_role을 뺀 요청으로 한 번 재시도**해 구성원 추가 자체는 막히지 않게 한다("자리는 저장하지 못했어요" 배너). 빈 선택은 전송하지 않는다. 화면 표기 이름은 시드 `seat_roles`(운전석 / 조수석 길잡이 / 뒷좌석 탐험가)를 쓴다.
13. **영수증 응답 상태 확장(02문서 11절)**: `status`는 `accepted | pending | rejected`. `pending`(확인 대기)은 "같은 제휴처·같은 날의 두 번째 영수증은 확인 후 적립돼요." 카드로 표시. `rejected` 사유는 `no_visit · duplicate · duplicate_photo · daily_limit · invalid_amount · missing_photo` 등을 한국어 한 줄로 매핑하고, 모르는 사유는 `(사유: 코드)`로 그대로 보여 준다.
14. **숙소(lodging) 영수증**: `stay_checkin`/`stay_checkout`(YYYY-MM-DD)을 multipart에 함께 보낸다. 클라이언트 검증: 체크아웃 > 체크인, 최대 3박. 현재 서버가 `paid_at`을 필수로 받고 있어, 숙소는 **체크인 날짜 `T12:00:00+09:00`을 임시로 `paid_at`에 실어 보낸다**(서버가 숙박 기간 판정으로 바뀌면 이 값은 무해). 숙소에서는 결제 일시 입력란을 숨긴다(식당·가게만 결제 일시).
15. **기기 토큰(00문서 13절)**: 가족 코드 **생성**(`POST /v1/families`)과 재발급(`POST /v1/families/me/rotate-code`)에 `X-Device-Token` 헤더를 함께 보낸다. 토큰은 첫 방문 시 `crypto.getRandomValues`로 만든 32자리 16진수를 localStorage(`aro_device_token`)에 발급·보관한 랜덤 값이며 개인정보가 아니다. **429 / `device_limit`** 응답 시 "하루 한 번만 만들 수 있어요. 기존 코드로 접속해 주세요." 안내 카드를 보여 준다. 서버가 미반영이면 헤더는 무시된다.
16. **memories.party_size(02문서 10절)**: "그때 함께 간 인원" 선택 입력(1~8). 골랐을 때만 multipart `party_size` 필드에 넣어 보낸다. 서버 미반영이면 무시된다.
17. **제휴처 kind 표기(00문서 13절)**: `restaurant`→맛집, `shop`→가게, `museum_shop`→**가게**, `lodging`→숙소. 서버가 kind를 안 보내면 '가게'로 표기한다.
18. **문구 규칙**: 화면·결과 카드 모두 **"포인트 캐시백(예시)"**와 "예시(시뮬레이션)" 표기를 쓴다. 환급·입금·원 단위 지급처럼 읽히는 문구는 쓰지 않는다(00문서 13절).
19. **세대(generation)는 문자 라벨**: 실서버의 `MemberIn/MemberOut.generation`은 문자(최대 20자, 예: `부모대`)다. 웹은 라벨 문자열을 보내고, 응답의 세대 값은 문자면 그대로, 숫자(구버전)면 조부모대·부모대… 라벨로 바꿔 표시한다.
20. **B4 인원 비교 문장 접기(2026-11-11)**: `GET /v1/families/me/settings`가 `fold_person_comparison_all`(boolean)과 `folded_place_ids`(배열) 두 필드를 **모두** 줄 때만 가족 관리에 설정 카드를 보여 준다(하나라도 없으면 카드를 아예 숨긴다 — 가짜 동작 금지). **카드가 보이려면 서버에 이 GET 라우트가 있어야 한다** — 같은 경로에 PUT만 있으면 GET은 405가 되어 카드가 숨겨진다. 초기 조회 실패(404·405·오류)는 배너 없이 조용히 숨겨 기존 화면 흐름을 해치지 않는다. 전체 스위치는 `PUT /v1/families/me/settings {"fold_person_comparison_all": bool}`(실패 시 체크박스를 원래 값으로 되돌림), 장소별 해제는 `DELETE /v1/families/me/folded-places/{place_id}`. 저장·해제 뒤에는 GET으로 다시 읽어 화면을 맞춘다. `folded_place_ids`는 코스·장소 목록(`GET /v1/courses`)의 id와 문자열 비교해 "코스 · 장소명"으로 표시하고, 목록에 없는 id는 "장소 {id}"로 보여 되돌리기가 항상 가능하다. 접기 추가(POST /v1/families/me/folded-places)는 차량 화면 몫이라 웹에서는 보내지 않는다.
21. **B5 사진 속 사람 이름(2026-11-11)**: 사진을 고른 경우에만 `POST /v1/memories` multipart에 `markers` 필드(JSON 문자열, `[{ "x": 0.42, "y": 0.33, "name": "할아버지" }]`, x·y는 사진 크기 대비 0~1 비율, 소수 셋째 자리)를 추가한다. 사진이 없거나 점을 안 찍었으면 필드 자체를 보내지 않고, 서버가 미반영이면 multipart의 여분 필드로 무시된다. 기존 필드(place_id·year·note·vehicle_label·party_size·photo)는 그대로다. 이름은 별칭만(실명 금지), 웹 입력 한도는 최대 20자·10명(서버 한도 50자·20개보다 좁다). 표시는 이름만 글로 한다 — then-now 상세는 `past.markers`, 타임라인 행은 항목의 `markers`가 배열로 올 때만 "사진 속 사람: …"을 덧붙인다(필드가 없으면 숨김). 좌표를 쓰는 표시는 차량·앱 몫이다. 저장한 이름표를 나중에 고치는 화면(`PUT /v1/families/me/memories/{id}/markers`)은 웹에 아직 없다. 얼굴 자동 인식·외부 라이브러리는 없다.
22. **타임라인 확장 필드(2026-11-11 감사 수정)**: 타임라인 응답의 기록(memory) 항목은 **`year`**(그때 연도)를, 방문(visit) 항목은 **`visit_ordinal`**(같은 장소 기준 1부터 시작하는 순번)과 **`trip_km`**(이번 코스 주행거리 km, null 허용)을 함께 준다고 본다(실측: 백엔드 `GET /v1/families/me/timeline`이 모두 제공). 표시는 "그때 1994년", "N번째 방문", "함께 달린 거리 N km"이며, 필드가 없거나 null이면 그 부분만 숨긴다(가짜 동작 금지). then-now 상세의 "지금" 카드도 응답의 `visit_ordinal`과 `now.trip_km`을 같은 규칙으로 표시한다. "새로고침"·"다시 시도" 버튼은 페이지 전체를 다시 붙이지 않고 목록 컨테이너만 비우고 다시 읽는다(기존에는 render를 재호출해 제목·목록이 2벌로 붙었다 — 코스 화면의 "다시 시도"도 같은 버그라 함께 고쳤다).
23. **가족 누적 주행거리(2026-11-11 감사 수정)**: `GET /v1/families/me/metrics`가 **`family_total_trip_km`**(숫자, km)를 줄 때만 타임라인 위쪽에 "우리 가족이 함께 달린 거리: N km (코스 주행 기준, 예시)" 한 줄을 보여 준다. 같은 코스 주행(course_run)은 서버가 1번만 합산한다. 조회 실패·필드 누락이면 조용히 숨긴다(타임라인 자체는 계속 동작).
24. **포인트 내역 제휴처 이름(2026-11-11 감사 수정)**: `GET /v1/families/me/points`의 entries에는 제휴처 이름이 없고 `reason`이 **`"receipt:{제휴처 id}"`**(예: `receipt:p-demo-ssambap`)로만 온다(실측). 웹은 **제휴처 이름 캐시**를 만든다: `App.loadPartnerNames()`가 전체 장소(`App.loadPlaces()`의 코스·장소 목록)마다 `GET /v1/places/{id}/partners`를 불러 `{id: name}` 지도를 만들어 두고(첫 성공 후 앱 실행 내 캐시, 서버 주소 변경 시 무효화), 내역 렌더 시 `receipt:` 접두어의 id를 이름으로 바꿔 표시한다. 이름을 못 찾으면 내부 식별자를 노출하지 않고 **"제휴처 영수증"**으로 표시한다. 서버가 entries에 `partner_name` 같은 이름 필드를 나중에 주면 그 필드를 우선 쓰도록 바꾸면 좋다.
25. **이어받을 사람·관리 권한 이전 후보(2026-11-11 감사 수정)**: 구성원 목록의 `role`(`owner | member | heir`)을 보고 **`role === 'owner'`인 본인은 두 선택 목록(이어받을 사람 지정·관리 권한 이전)에서 아예 제외**한다. 서버는 owner 대상 지정을 400 `already_owner`로 거부하므로(실측), 처음부터 목록에 보이지 않게 하는 것이 맞다. 그래도 서버가 거부하면 api.js의 코드별 문구("관리자 본인은 선택할 수 없어요…")로 배너 한 줄을 보여 준다. 후보가 없으면 "관리자를 제외한 구성원이 없어요"를 표시하고 선택을 막는다.

## 한계 · 법적 문구 (02문서 3-1 · 6-4절 반영)

- **물려주기(관리 권한 이전)**는 앱 안의 관리 권한을 넘기는 기능일 뿐 **법적 상속이 아니다**. 자동 실행이 없고, 이전 뒤에도 기록은 지우지 않는다. 실제 서비스화 시 본인 확인·법적 검토가 필요하다.
- **제휴처·적립 재원·정산은 아직 없다**(협의 필요). 데모 제휴처는 가상의 이름이며, 적립은 전부 **예시(시뮬레이션)** 이다. 포인트의 현금 가치·사용처를 약속하지 않는다.
- 실제 포인트 발행·정산에는 관련 법규 검토와 결제 수단 연동이 필요하다.
- 영수증 진위 확인(OCR·가맹점 대사)은 구현하지 않았다.
- 이 웹은 위치를 읽거나 보내지 않는다. 사용자 실시간 위치·이동 경로는 저장·전송하지 않는다(02문서 3절).

## 오류 표시 정책

- 서버/네트워크 오류: 상단 배너 한 줄(3초). 서버가 `{ error: { code, message } }`를 주면 코드별 한국어 문구를 쓰고, `message`가 있으면 우선 표시.
- 콘솔 로그는 `[aro] METHOD /path -> status code` 한 줄만 남긴다(개인정보·입력값 금지).
- 렌더링 중 예외도 잡아서 배너로 표시한다(흰 화면 방지).
